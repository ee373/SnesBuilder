# Rev.0.9 RISC-VファームウェアとSFC BIOS

AG32VF407VGT6のRISC-V CPUは、ゲームローダ、NOR消去・書込み、セーブデータ退避・復元、USB Full-Speed、microSD SPI、ゲーム固有の演算・音声プログラム、FPGA制御を担当する。通常のSFC ROM読出しはFPGAが直接処理し、RISC-Vはアクセスのたびには介在しない。外部NOR/SRAMへのアクセスはFPGA経由のAHBメモリコントローラを使用する。

## メモリごとのソフトウェア配置

| 実体 | 役割 |
|---|---|
| AG32内蔵Flash | カートリッジ共通システムファームウェア、起動ローダ、SFC用標準65C816プログラム、フォント等の共通リソース、Jet 3Dレンダラー、cmixer 16音ミキサー、SRAM退避・復元プログラム、FPGA構成データ |
| AG32内蔵SRAM 128KiB | 外部NORからロードしたゲーム固有RISC-V実行コード、定数・初期化済みデータ、BSS、スタック・ヒープ、必要なCPU/FPGA共有バッファ |
| 外部パラレルNOR 8MiB | SFCゲームROM、ゲーム固有のRISC-Vバイナリ、画像・音声等のゲームリソース |
| 外部SRAM 128KiB | 起動時のSFC用BIOS（末尾8KiB）、ゲーム実行時のセーブ・共有データ（全128KiB）、電源断時の永続退避（先頭120KiB） |
| 外部SPI NOR 256KiB | 電源断時の外部SRAMセーブデータの二重化保存 |

内蔵Flashはゲームごとに書き換えず、カートリッジ標準機能を保持する。SFC側の標準プログラムは65C816用バイナリとして内蔵Flashに保持し、起動時に必要な部分を外部SRAMへ展開する。SFCが内蔵Flashを直接メモリマップして実行する接続は設けない。ゲーム固有のRISC-VコードはARMコードではなく、AG32のRV32IMAFC向けにビルドする。

内蔵SRAMに展開するRISC-Vアプリケーションの実行アドレスは `0x20000000` を基点にする。共通ファームウェアの作業領域、スタック、割り込み状態、必要な共有バッファをアプリケーションの展開領域から除外する。128KiB全体をゲームコード専用に固定せず、実際の必要容量をリンカスクリプトで決める。内蔵Flashの使用可能サイズとFPGA構成データの配置は採用するSDK/ブート構成に合わせて確定する。

## 起動シーケンス

1. 内蔵Flashの共通ファームウェアからAG32を起動し、電源、CIC、各OEの安全状態、FPGA/AHB、外部MEMを初期化する。この間はSFC /RESETを保持する。
2. SPI NORの128KiB×2バンクを検査し、CRC・世代番号・保存完了マーカーが正常な最新世代を外部SRAMの物理先頭120KiBへ復元する。次回退避先のバンク消去は通常給電中に行う。
3. 内蔵Flashに保持したSFC側標準プログラムを外部SRAM物理`0x1E000～0x1FFFF`の8KiB BIOS領域へ展開する。フォント等の共通リソースは用途に応じてSFC側へ転送する。
4. FPGAがMEM所有権をCPUに与えた状態で、外部8MiB NORに同梱したゲーム固有RISC-V実行イメージを内蔵SRAMの指定アドレスへロードする。ゲームROMとRISC-Vイメージの物理配置はパッケージのメタデータで指定し、両者が8MiB内で重複しないようにする。
5. 初期化済みデータ/BSS、スタック、割り込みベクタ、共通ファームウェアとのAPI境界を準備し、命令フェッチの同期（`fence.i`等）を行って、RISC-VのPCを内蔵SRAM上のアプリケーションエントリポイントへ移す。共通システム機能と電源断退避処理は内蔵Flashに残す。
6. ROM形式・容量、MEM所有権、通信窓/FIFOを設定し、RISC-VがBOOT_CONTROLでBOOT_MODEとSRAM BIOS窓を有効にしてから、SFC /RESETを解除する。FPGAは`$00:FFFC/FFFD`へ`00/80`、`$00:8000～8003`へ`5C/00/60/2F`を返し、SFCは`JML $2F6000`で外部SRAMのBIOSへ進む。BIOSからの要求を受けたRISC-VがBOOT_MODEを解除し、BIOS窓は必要な間維持する。

ゲームパッケージは65C816 ROM、RISC-V SRAM実行イメージ、リソース、セーブ定義で構成する。初期テストはPVSnesLib HiROM/SlowROMとし、ROM4形式・7段階容量ミラー・非2冪の展開ルールをFPGA/ローダが扱う。

## GCC・リンカと共通ファームウェア

RISC-Vのゲーム側バイナリはGCCで内蔵SRAMの実行アドレスへリンクし、NORにはそのロードイメージを格納する。単純な固定アドレス実行イメージなら実行時の一般的な動的リンカは必要ない。共通Flash側とゲームSRAM側は別のリンカ設定を用意し、共通ファームウェアのAPI（Jet・cmixerを含む）は固定の呼出しテーブル/ABIを通じて公開する。共通ファームウェアの必要なRAMとゲーム用RAMはリンカで非重複にする。ブートローダのスタックはゲームイメージのコピー処理中に上書きしない場所へ配置する。

SFC（65C816）は`$5001 COMMAND`、`$5003 REPLY`、`$5005 TX_DATA`、`$5006 RX_DATA`等の通信レジスタ経由でRISC-Vへコマンド・データを送り、結果を受け取る。`$5000`はCPU_CONTROL専用とする。RISC-Vから追加のFPGA演算アクセラレータを使用する場合も、内部AHBの入力/制御レジスタへ書込み、状態/出力レジスタから結果を取得する。これらのAHBメモリマップドレジスタはアプリケーションのリンク先RAMではなく、ドライバからMMIOとしてアクセスする。アドレスはPrepare LOGICの生成トップで最終確定する。

## 共通メディアライブラリとアプリ停止・再開

`$5000 CPU_CONTROL` bit0は0でゲーム固有RISC-V処理の実行・再開、1で停止を要求する。起動時は0とし、`$5002 STATUS` bit3で停止完了を通知する。FPGAが停止要求を保持し、共通ファームウェアがアプリの実行を安全な制御境界で中断する。停止中も共通ファームウェアのSFC通信・MEM調停・電源断バックアップを維持し、RISC-Vコア全体のクロック停止は行わない。共通制御割り込みからゲーム固有処理を中断・再開する仕組みを実装時に検証する。

Jet（C++17ソフトウェア3Dレンダラー）とcmixer（ANSI Cの軽量PCMミキサー）は内蔵Flash上の共通ライブラリとして配置し、RISC-Vのゲーム固有C/C++コードから固定ABI経由で直接利用する。モデル・頂点・テクスチャ・音声素材は外部NORなどのゲームリソースとして管理し、実行時バッファは内蔵SRAM128KiBを共通ファームウェア・アプリ・Jet・cmixerで分け合う。65C816用の3D/音声専用レジスタを設けず、ゲームごとにRISC-V上の処理を定義する。激ツヨ森田将棋ではRISC-Vを思考エンジンに用い、Jet/cmixerを実行しない。

Jetは現行の152×104（128画素8bpp＋24画素RGB555）表示経路へ適合する素材を生成する。約60フィールド/秒でシーンを更新することを目標とし、2フィールド1組の104ライン画像はプログレッシブ60fpsではない。cmixerは最大16音を64 kHz・符号付き16 bitステレオPCMへミキシングし、AHB経由でFPGAの64フレームFIFOへ供給する。SFC標準SPC700/S-DSPの8音と合わせて24音の同時発音を目標とする。実際のFlash使用量、SRAM使用量、Jetとcmixerの並行動作性能はAG32向けビルド・実機で確認する。[音声MMIOと再生制御](audio.md#risc-vのpcmレジスタ)

OS起動演出では、SFCのPPUとDMA/HDMAの初期化後にJetのリアルタイム3Dロゴとcmixer/DSMの短いジングルを再生する。MEM通信、映像更新、PCM FIFOの内部状態を起動時診断に利用し、実際のPPU表示・アナログ音声は画面と音で確認する。

## 電源断時のSRAMバックアップ

AG32 PIN24のアクティブHigh `POWER_FAIL`を受ける退避処理は**内蔵Flashに常駐する共通ファームウェア**が担当し、ゲーム固有のSRAMアプリケーションには依存しない。電源断時は退避専用スタック/割り込み状態へ移り、SFCデータバスの出力を無効にしてMEM所有権をCPUへ移行する。AG32は低クロックRunで動作し、USB・音声・microSD等を停止、必要なFPGA/AHB・外部SRAM・SPI NORのみを動作させる。

外部SRAMの物理`0x00000～0x1DFFF`（120KiB）を消去済みSPI NORバンクへページ書込みし、書込み完了待機、CRC・世代番号の記録、保存完了マーカーの最終確定まで実施する。旧バンクは新バンクの保存完了まで保持する。内蔵FlashやmicroSDへ電源断セーブデータを書き込まない。電源断後のFlashコード実行と内蔵SRAM/スタック、FPGA/AHB、必要なメモリの給電維持はHiCAP動作条件に含める。

HiCAP充電完了監視や充電完了までの起動待ちは設けない。電源断割り込みとMEM所有権の順序、電源復帰時の遷移、最悪保存時間・保持時間、Flash常駐退避コードの独立性、SFC側無給電時の逆給電を実機で検証する。
