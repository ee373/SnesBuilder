# Rev.0.9 3Dグラフィックス実証計画

更新: 2026-11-20。状態: **採用した表示方式の設計目標（未実装・未実機検証）**。AG32VF407VGT6（RV32IMAFC、最大248MHz、CPU内蔵SRAM128KiB）で3D描画を行い、SFCのPPUへ表示する。ハードウェア本体Rev.0.9の仕様は変更しない。**この表示方式はUSB映像転送モードにも共通採用する。** 画像生成元・共有SRAM・65C816・PPUをつなぐ全体経路とUSB受信時の処理は[SDK・USB連携](../../sdk-emulator.md#カートリッジからsfc本体への映像転送)に記載し、この文書では3D描画とMode 3・BG1 8bpp表示の転送量・検証条件を扱う。

## 1. 採用する表示方式と目標

**本命はMode 3のBG1（8bpp）に統一した、V-BlankのVRAM部分更新＋H-BlankのCGRAM/スクロールHDMA併用方式**とする。1枚のBG1内で、通常パレット番号の画素データをV-Blankに更新する領域と、固定画素番号が参照するRGB555のCGRAM色情報をH-Blankで更新する領域を横方向に配置する。RISC-Vが頂点変換、投影、クリッピング、ポリゴン描画、Zテスト、必要なパレット化とタイル変換を担当し、SFCの65C816がDMA/HDMA、PPU設定、共有SRAMからの転送、入力・同期を担当する。

| 項目 | 基本目標 | ストレッチ目標 |
|---|---:|---:|
| 画像情報の目標解像度 | **116×112** | **124×112** |
| V-Blank側（BG1・8bpp画素番号） | 88×112 | 96×112 |
| H-Blank側（BG1・CGRAMのRGB555独立色） | 28×112 | 28×112 |
| 表示方式 | NTSCの約60フィールド/秒、インターレース | 同左 |
| 1フィールド当たりの画像情報 | 56ライン | 56ライン |
| 1フィールドのV-Blank向け8bpp画像データ | **4,928 B** | **5,376 B** |
| 1フィールドのH-Blank向けRGB555色情報 | **3,136 B** | **3,136 B** |
| 目標の状態 | 帯域上の設計候補 | 帯域上の設計候補 |

表の112ラインは偶数・奇数フィールドに56ラインずつ異なる画像情報を与える構想の論理解像度であり、**Mode 3で均等な112行の空間解像度として見えることや、60枚/秒の完全なプログレッシブ画像が表示されることを意味しない**。1組の完全画像は2フィールドで構成されるため約30組/秒であり、各フィールドで新しい画像を生成する場合は動きの更新頻度が約60Hzとなる。フィールド位相、行の表示位置、ちらつきは実機で評価する。

## 2. CGRAM割り当てと色表現

Mode 3のBG1は8bppでCGRAMの256エントリを参照する。背景の色番号0は透明として予約し、ダブルバッファとなる動的領域を28色×2組確保する。

| 領域 | エントリ数 | 用途 |
|---|---:|---|
| 透明番号0 | 1 | BG1透明 |
| 通常パレット | **199** | V-Blank更新の8bpp画素が共通参照 |
| 動的パレットA | 28 | H-Blankで更新するRGB555 |
| 動的パレットB | 28 | 表示中と更新中を交互に切り替えるRGB555 |

`256 - 1 - 28×2 = 199` であり、通常側は199色の共通パレットから各画素が色を選択する。動的側は各画像ラインの28画素にそれぞれ独立したRGB555を指定する。CGRAM上のA/B番号を表示行ごとに切り替えられる**固定8bppタイル配置**が必要であり、タイル境界での画素番号配置、垂直スクロールとの整合、隣接行の表示中に更新対象パレットが参照されないことを検証する。CGRAMは1エントリ2バイトで、通常側も最終出力の色精度はRGB555となる。横方向の28画素は8×8タイルの単位では4タイル＝32画素を占有するため、残る4画素は固定透明番号0などで表示から除外し、V-Blank側との境界位置を固定する。A/Bの動的パレットは通常画像の画素番号に割り当てない。

## 3. V-Blank転送の計算

インターレースの1フィールドで56画像ライン分を更新する想定で、V-Blank側8bppの画像データ量は `W × 56 × 1 byte` とする。

- 基本目標: `88 × 56 = 4,928 B/field`。8×8タイルでは横11枚×縦7枚×64B＝4,928B。
- ストレッチ: `96 × 56 = 5,376 B/field`。横12枚×縦7枚×64B＝5,376B。

NTSC 224走査線表示のV-BlankはDMAに使える時間が限定される。上記は**純粋なタイル画素データ**であり、DMAレジスタ設定、VRAMアドレス、他のPPU更新、必要なタイルマップ更新、CPU処理時間は含まない。約6KB程度の理論転送枠を実際に利用できるか、実機相当のスケジュールで確認する。カートリッジ側RISC-VからPPUのVRAMに直接書き込む構成ではなく、65C816が共有SRAMからDMA転送する。

## 4. H-BlankでのCGRAM更新とBG1垂直スクロール

224本/フィールドに対し56画像ライン/フィールドを割り当てる構想なので、**4走査線当たり1画像ライン**に相当する。CGRAM側は1ライン28色×2B＝56B、1フィールド56ラインで `28×56×2 = 3,136B` の色情報を必要とする。

検討中のHDMAチャネル割り当ては次のとおり。

| HDMAチャネル | 機能 | 想定 |
|---|---|---|
| 0～6（7本） | CGRAMのアドレス設定＋RGB555色情報 | 合計7色/走査線の更新を仮定 |
| 7（1本） | BG1垂直スクロール（$210E, BG1VOFS） | 各走査線で2回のレジスタ書き込み |

理論上、`7色/走査線 × 4走査線 = 28色/画像ライン`。色情報は1走査線14B、CGRAMアドレス設定を2Bと置く場合はCGRAM側16B、BG1VOFSの2Bを加えて計18B/走査線となる。224走査線でレジスタ転送データは計4,032B/フィールド（HDMAテーブルの制御バイトは別）である。垂直スクロール値は2B×224走査線＝448B/フィールドを基本量とし、HDMAの行数カウンタやテーブル境界の制約を別途見積もる。背景の参照行を4走査線ずつ同じ行とするために、BG1VOFSを走査線ごとに補正する。BG1を1枚に統一しているため、**VOFSの変更は通常画素領域と動的パレット領域の双方に適用される**。固定タイルの参照行とA/Bパレットの切り替えを含めて設計する。

**7色/走査線は未検証の帯域仮定である。** HDMAチャネルの転送モードにより$2121（CGRAMアドレス）および$2122（色情報2バイト）のアクセス順序を正しく作り、各走査線のCGRAM書き込み可能なクロック位置を含めて検証する。HDMA転送に必要な総クロック数がH-Blankの長さ以下という計算だけでは、CGRAMへの実書き込み成立を保証しない。複数チャネルが同じCGRAMレジスタを使用する場合のアドレス自動インクリメントと転送順序も確認する。

インターレースのMode 3ではMode 5/6のようなBG垂直画素の自動倍解像度選択を前提としない。フィールドごとの表示行選択、スクロール補正、画素位置およびA/Bパレット選択の整合を実測する。

## 5. RISC-V→SFC描画データ経路

1. RISC-Vが内蔵SRAMでモデル座標変換、投影、クリッピング、ラスタライズ、Zテスト、テクスチャ参照を行い、フィールド別の画像データを生成する。初期評価では画像を生成する時刻と実表示フィールドをそれぞれ記録する。
2. 通常側画素は199色共通パレットの8bpp番号へ変換し、8×8・8bppタイルのビットプレーン形式に変換する。動的側28画素のRGB555値を画像ライン順のHDMAデータとする。BG1のA/B用固定タイルパターン・タイルマップも用意する。
3. RISC-Vが共有外部SRAMへ転送素材を配置し、FPGAのAHB・共有MEM所有権調停を経由して65C816から参照可能にする。SFCはV-BlankでVRAM画素データを更新し、可視期間はHDMAでCGRAMとBG1VOFSを書き換える。
4. フィールド境界でのバッファの所有権と、VRAM転送、HDMAテーブル更新、表示対象の切り替えを同期する。DMAの転送途中データや更新中のパレットが可視になることを防止する。

理論画像バッファ容量は116×112の8bitリニア表現が12,992B、16bitのRGB555/Zバッファが各25,984B。124×112では8bitが13,888B、16bitのRGB555/Zが各27,776B。内蔵SRAM128KiBには実行コード、スタック、頂点、テクスチャ、変換バッファも必要なので、実使用量を測定して配置を決定する。

## 6. 参考設計：4bpp BG2＋8bpp BG1の混合方式

**本命の8bpp統一方式とは別の構成として、設計比較に必要な情報をここに保存する。** Mode 3のBG1（8bpp）で28色/画像ラインのRGB555更新を行い、BG2（4bpp）ではV-Blankに画素番号を転送する。BGの透明部分を左右で分担して合成し、BG2VOFSをHDMAで補正する。

| 項目 | 参考設計の基本構成 | 参考設計の拡張構成 |
|---|---:|---:|
| 論理画像解像度 | **188×112** | 220×112 |
| BG1（8bpp／HDMA） | 28px | 28px |
| BG2（4bpp／V-Blank） | 160px | 192px |
| BG2画素データ／フィールド | 4,480B | 5,376B |
| BG1色情報／フィールド | 3,136B | 3,136B |

BG2は4bppの16色×8パレット（各パレットの色番号0は透明）を使用し、BG1動的パレットとはCGRAM領域を分離する。V-BlankのBG2転送量は `160×56÷2=4,480B` または `192×56÷2=5,376B`。こちらもHDMAの7色/走査線、VOFSの表示行再利用、Mode 3のフィールド表示位置など、本命方式と同じ未検証事項がある。参考方式の実装を必須工程とはしない。

## 7. 検証手順・合格条件

| 工程 | 検証内容 |
|---|---|
| P0 | 1走査線内の$2121/$2122へのHDMA転送順序・CGRAM書き込み可能期間を確認し、更新可能色数を測定 |
| P1 | BG1の8bpp固定画素番号とCGRAM A/B領域で、表示中の色が更新されないことを検証 |
| P2 | HDMAの1チャネルをBG1VOFSへ割り当て、縦方向の行再利用とCGRAM更新の同時実行を検証 |
| P3 | 偶数・奇数フィールドの表示行配置、60フィールド/秒の更新、色の混在・ちらつきを実機とエミュレータで測定 |
| R0 | RISC-V上で座標変換・ポリゴン・Zテストを計測し、8bpp共通色とRGB555動的色への変換を実装 |
| R1 | 116×112目標のVRAM DMA、共有SRAM、HDMAテーブル生成・更新同期を評価 |
| R2 | 124×112目標の転送余裕とFPS、画素処理量、CPU・FPGA資源を評価 |
| 任意 | [INT16×4ドット積MAC](../../roadmap.md)等のアクセラレータをCPU単独処理と同条件で比較 |

検証では、画像の論理解像度、1フィールドの新規画素数、RGB555色の正常更新数、実表示される縦方向の独立位置数、フィールドレート、完全画像の更新レート、描画FPSを別々に記録する。加えて、65C816のHDMA占有時間、DMA完了時刻、VRAM/CGRAM転送バイト数、RISC-Vの描画時間、共有SRAM待機、内蔵SRAM使用量、FPGAのLUT/FFを測定する。

**未検証の7色/走査線・56行×2フィールド表示を既成事実として扱わない。** 本命の8bpp統一方式は設計採用であり、性能達成はP0～P3の結果に依存する。
