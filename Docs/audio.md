# Rev.0.9 追加ステレオPCM音声・1bit ΔΣ（DSM）出力

2026-11-20 更新。現行Rev.0.9の追加音声は、**RISC-Vによるソフトウェア音源／DSP処理＋FPGAによる左右独立1bit ΔΣ変調（DSM）**を目標構成とする。PCMサンプリング周波数は**64kHz**、DSM変調クロックは既存8MHz水晶由来の**8MHz**を初期目標とする。従来の**10bit DAC・32kHzステレオPCM案は比較・代替候補**として残す。これらは設計目標であり、ピンフィッティング・回路合成・実機音質測定はこれから行う。

## 1bit DSM方式の信号経路とピン

```text
NOR / microSD / USB / SFCからの制御
             ↓
AG32 RISC-V（PCM生成・復号・ミキサー・EQ・エフェクト、内部16/32bit処理）
             ↓  32bit AHB、PCMサンプルFIFO／二重バッファ、CDC
FPGA（64kHzサンプル更新、DSM L/R、8MHz変調クロック）
             ├→ AG32 LQFP100 PIN29（DAC0兼用IOをFPGAデジタル出力）→ DSM用LPF → MCP6002左 → SFC AUDIO L端子31
             └→ AG32 LQFP100 PIN30（DAC1兼用IOをFPGAデジタル出力）→ DSM用LPF → MCP6002右 → SFC AUDIO R端子62
```

- PIN29/PIN30はDAC0/DAC1兼用のデジタルIOであり、DSMモードではアナログDAC機能を無効化する。Prepare LOGICのユーザーIO割当候補をそれぞれ `audio_dsm_l PIN_29:OUTPUT`、`audio_dsm_r PIN_30:OUTPUT` とし、実際の生成トップ／Supra Nativeによる割当・配置配線で駆動可能なことを確認する。ピン番号やSFC端子の外部配線は変更しない。
- AG32のPIN12/13に接続する既存の8MHz水晶をクロック源とする。FPGA側の`PIN_HSE_OUT`等の利用可能なクロック経路をPrepare LOGICの生成結果で確認し、DSMロジックへ8MHzを供給する。追加の水晶発振器や専用クロック入力GPIOは計画しない。
- `8,000,000 Hz / 125 = 64,000 Hz`なので、64kHzのPCM更新と8MHzのDSMを整数比で同期できる（OSR=125）。クロック周波数の**精度は水晶の実際の誤差・温度特性に従う**。CPUのPLLクロックとはクロックドメインを分離し、AHB側PCMバッファからHSE/DSM側への受け渡しは非同期FIFO、トグルハンドシェイク等で安全に同期させる。
- DSMの一次変調器から機能確認し、二次変調器、ビット深度、安定性・オーバーフロー対策、量子化ノイズの帯域外シフトを検討する。1bit出力自体が「1bit音質」を意味するものではなく、達成可能なSNR/SINAD/THD+Nは回路と測定で決まる。

## アナログ出力回路とDAC比較

現行の `PIN29/30 → LPF → MCP6002 → SFC外部AUDIO L/R` の**信号経路は維持**する。ただし、従来10bit DAC出力用のLPF定数が8MHz DSMの高周波成分を十分に減衰させるとは考えず、DSM用に遮断周波数、次数、利得、直流バイアス、出力負荷、電源由来ノイズ、出力電圧振幅を再設計・測定する。MCP6002入力段へ高周波成分が過大に到達しないよう、必要な受動LPFをオペアンプより前に置く。DSM出力の矩形波に起因するEMI、電源リップル、左右クロストーク、ポップノイズも評価する。

旧10bit DACモードとの切替は、同一のGPIOを別機能で使用するため**排他的**とし、DSP内部演算分解能とアナログ出力の実効分解能を混同しない。64kHzの出力を実現するまでの比較基準として、従来の10bit／32kHz動作も保持する。

## ソフトウェア音源・DSP機能

- RISC-VがPCM復号、ソフトウェアミキシング、音源別パン／音量、EQ・フィルタ・エフェクトを担当する。初期デモ目標は8ch PCM、次に16ch、5バンドEQ、ローパス／ハイパス、簡易ディレイ／リバーブ、コーラス、リミッタを段階的に追加する。全機能同時稼働はCPU占有率とメモリ帯域を測って決める。
- 5バンドEQは左右各5段のbiquadを候補とし、係数更新時のクリック防止、固定小数点または単精度FPUの精度・処理負荷、内部ミキサーのヘッドルーム、最終出力のディザ／飽和を評価する。
- 64kHz・16bit・ステレオの**1秒分の未圧縮PCMは256,000バイト**となる。内蔵SRAM128KiBにはコード／スタック／ミキサーも配置するため、長いステレオディレイや大量のサンプルを内部SRAMに全量保持しない。共有外部SRAMを利用する場合はSFCとのMEM所有権調停、NORサンプル読出しでは8bit共有バスの転送待機時間を計測する。
- SFC標準のSPC700/S-DSPによる8ch音声を消費せず、カートリッジ側の追加音声として利用する。現行配線では**標準SPC700音声全体をRISC-V側でEQするものではない**。SFC側からの制御は既存の`$5000`通信窓／FIFO・IRQを使用し、PCMバッファアンダーラン時の出力と回復手順を定義する。

## 実装・検証条件

1. FPGAのPIN29/30出力割当、`PIN_HSE_OUT`等のクロック経路、8MHz動作、生成トップのAHBおよびクロックドメイン間同期を合成・配置配線で確認する。既存のROMマッピング、MEM調停、通信FIFOのタイミングを優先する。
2. DSMのL/R独立出力をロジックアナライザで確認し、64kHz更新、8MHzビットストリーム、無音時のアイドルパターン、飽和・異常復帰を検証する。
3. LPF・MCP6002・SFC外部AUDIO端子の波形と周波数特性、SNR/SINAD、THD+N、左右分離、スイッチングノイズ、出力振幅、ポップノイズを測る。10bit DAC方式と同一条件で比較する。
4. 多重PCM、5バンドEQ、フィルタ、リバーブを追加し、RISC-V CPU負荷、サンプル落ち、内部／外部SRAM使用量、共有MEM帯域を測定する。

音声実証の操作シナリオと測定順序は[音声デモ計画](prototypes/audio-demo/README.md)を参照する。関連する物理配線は[hardware.md](hardware.md)、開発手順は[fpga-development.md](fpga-development.md)を正本とする。
