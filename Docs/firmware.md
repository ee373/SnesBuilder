# 共通BIOS・ファームウェア・ゲームパッケージ

Rev.0.8 / 基本設計段階（2026-11-19）

## 1. ARM側の内蔵メモリ

256KiBの内蔵フラッシュにはARM共通BIOS、65C816用SFC側BIOSイメージ、ブートローダ、制御ライブラリを配置する。SFC側BIOSは外部NORに保持せず、起動・再起動のたびに外部SRAM末尾8KiBへ展開する（収まる容量で設計する）。

| 機能 | 内容 |
|---|---|
| ブートローダ | 起動、USB更新 |
| 初期化 | CPLDモード設定、GPIO、UDB、DMA、OEの安全状態 |
| NORドライバ | 読み出し、消去、書き込み |
| SRAMドライバ | アドレス変換、メモリアクセス |
| microSDドライバ | SPIによるアクセス |
| ファイルシステム | ゲームファイル管理 |
| バス調停 | SFC・ARM間の所有権制御 |
| コマンド処理 | SFC通信 |
| ゲームローダ | ARMプログラム展開 |
| セーブ管理 | SRAMとmicroSDの同期 |
| 共通ライブラリ | ゲーム向けAPI、数値演算 |

64KiBの内部SRAMにはゲーム固有のARMコード、ゲームワークメモリ、BIOS作業領域、転送バッファ、スタックを配置する。各領域の容量配分は未確定である。

```text
PSoC Internal SRAM : 64KiB
+-------------------------------+
| ARM Game Program              |
+-------------------------------+
| Game Work Memory              |
+-------------------------------+
| BIOS Work Memory              |
+-------------------------------+
| Transfer Buffer / Stack       |
+-------------------------------+
```

ARMゲームはCortex-M3向けのネイティブバイナリとして生成し、SRAMへロードして所定のエントリポイントから実行する。外部メモリ、microSD、通信レジスタ、DMA等は共通BIOS APIを通じて利用する。ABIとしてロードアドレス、エントリポイント、スタック、API呼び出し規約、BIOSバージョンを定義する（未確定）。

## 2. microSDとUSB/SWD

microSDはSPI（SCK、MOSI、MISO、/CS）で接続する。PSoCの5Vポートから出力するSCK、MOSI、/CSは74LVC245APW,118 #5で3.3Vへ変換し、AG256を経由せずmicroSDへ直接接続し、MISOはPSoCの3.3V SIOへ直結する。SPIはUDBによるハードウェア実装（高速SPI候補は18Mbps級）またはARMによるGPIOソフトウェア実装（同じピン配置）とする。メモリバス、通信、FIFOのUDB資源を優先して選択する。PSoC 5LPには固定機能SPI/SCBが存在しない。ソフトウェア実装時はP12の他のメモリ制御ビットを保持する。FAT系ファイルシステムを想定し、ゲーム、リソース、設定、セーブ、既存ROM向けパッチを保存する。

Full-Speed USBはPCとの通信、共通ファームウェア更新、ゲーム転送、デバッグ情報の取得、設定変更、開発用データの読み書きに利用する。USBプロトコルとPCツールはSDKと並行して定義する。

PSoCの初回プログラム書き込み、デバッグ、USBブートローダの復旧にはSWDを利用する。電源条件は[power-cic.md](power-cic.md)を参照する。

## 3. ゲームパッケージ

ファイル構成の暫定案:

```text
/
├── system/
│   ├── config.json
│   └── patches/
└── games/
    └── example_game/
        ├── manifest.json
        ├── game.sfc
        ├── arm.bin
        ├── assets.bin
        └── save.srm
```

| ファイル | 内容 |
|---|---|
| manifest.json | ゲーム識別情報と実行条件 |
| game.sfc | 65C816用プログラム |
| arm.bin | Cortex-M3用ネイティブコード |
| assets.bin | 画像・音源・各種リソース |
| save.srm | セーブデータ |
| config.json | カートリッジ設定 |
| patches/ | 既存ROM向けパッチ |

manifestにはゲーム名、バージョン、ゲームID、必要なBIOSバージョン、ARMコードの実行条件、ROMマッピング（HiROM、ExHiROM、LoROM、ExLoROM）・有効容量、NORへの事前ミラー展開規則、SRAM形式・使用容量、リソース情報などを記録する。正式な形式とフィールドはSDK仕様として確定する。

## 4. 開発カートリッジの起動処理

1. 電源投入時にCIC認証とPSoC初期化を開始する。PSoCの起動中はAG256のMEMアドレス15出力とLVC245A #1、8T245をHigh-Zとし、AG256のメモリ制御4出力はプルアップによってNOR/SRAMの/CE・/OE・/WEを非アクティブに維持する。CPLDの不揮発構成は固定とし、制御レジスタ/入力ピンによる動作モードを起動時に設定する。
2. PSoC起動後にSFC /RESET（P15[1]）をオープンドレインLowでアサートし、BIOS準備とゲーム用設定完了まで保持する。SFC本体のCICおよび/RESET駆動条件は実機で検証する。
3. ARMが共有MEMバスの所有権を取得する。AG256のMEMアドレス15出力、LVC245A #1、8T245をHigh-Zとする。メモリ制御信号はAG256だけが出力し、ARM所有時にはPSoCの4本のメモリ制御GPIOからAG256へ入力した値を選択する。PSoCはMEM A0–A22とD0–D7を直接駆動する。
4. ARMはゲームパッケージのROM形式、サイズ、ミラーリング、セーブ領域を解析する。HiROM・ExHiROM・LoROM・ExLoROMの形式と物理NOR配置が一致するよう、必要なバイトを事前展開する。同一イメージが既にNORに存在する場合は識別情報を比較して消去・書込みを省略する。
5. ARMが必要に応じてNORを書き込み、ゲーム用ARMネイティブコードを内蔵SRAMへ展開する。BIOSはPSoC内蔵Flashから外部SRAM末尾8KiB（0x1E000–0x1FFFF）に展開する。この領域は永続セーブ対象に含めない。
6. ARMはPSoC P15[3]の専用BOOT_MODE出力を74LVC245A #5経由でAG256へ通知し、$00:8xxx/$00:Fxxxのブート候補をNORから隔離する。PSoCは$00:FFFC–FFFDに$8000、$00:8000–8003に`JML $2F6000`の6バイトを返す準備をする。起動用のHiROM SRAM窓$2F:6000–$2F:7FFFを有効にしたまま、バスをSFCへ返却する。
7. SFC /RESETを解放する。65C816はPSoCの固定値応答から$2F:6000（物理SRAM 0x1E000）のBIOSへ移る。CPLDがSPECIAL_SELを出力し、PSoCはSFC A15/A0–A4と必要な中位アドレスで対象6バイトを判定する。
8. BIOSは$5000通信でBOOT_MODE解除を要求し、解除完了を確認する。SRAM BIOSを実行中はそのウィンドウを維持する。割り込みベクタを準備してから割り込みを許可する。
9. BIOSはStart＋Selectの同時押しでメニュー継続を選択し、指定がなければ前回ゲームの起動へ進む。ゲームの書込みや形式変更ではSFCをWRAMコード上へ移し、$5000通信でARMへ所有権を引き渡す。AG256のMODE_HILO/CFGとSRAM窓、8T245・LVC245A #1の/OEが安定してからSFCへ返却する。
10. WRAMコードがゲームROMのリセットベクタを取得してエントリポイントへ移る。BIOS再起動時にはSFCを再リセット保持し、SRAM BIOSを再展開して同じ固定値応答から開始する。

ゲームロード・NOR消去/書込みの間、SFCはWRAMコードによって表示や入力受付を継続できる。外部メモリ所有権は排他的とする一方、SFC D0–D7はPSoC P0[0:7]へ独立接続されるため、**ARM所有中も$5000レジスタ通信は継続できる**。

ブート固定値は外部ROMを使用せずPSoC UDBからSFCデータバスへ直接応答する。AG256は上位アドレスを判定し、NOR/SRAMと8T245データ側を非選択にする。SFC起動より前のリセット再アサート、データ出力競合、CICとの電気的整合、強制リセット時間は回路・実機で検証する。

## 5. セーブ管理

セーブはバッテリーバックアップ付きSRAMに保存する。次回起動時やゲーム切り替え時にmicroSDの対応ファイルへ書き出し、新しいゲームのセーブを読み込む。

PSoCの内蔵EEPROMには最後に実行したゲームの識別情報、SRAM使用状況、管理情報を保持し、SRAMに残っているデータがどのゲームに対応するかを判定する。ゲーム固有のセーブ領域の大きさや配置はSDK・パッケージで定義する。

## 6. 実行時USB通信と外部ホスト駆動

2026-11-17の検討によるソフトウェア拡張方針。Rev0.8のハードウェア（8MiB NOR、128KiB共有SRAM、64KiB内部SRAM、CPLDによる高速ROMアクセス、双方向FIFO・DMA、USB、SWD）を使用し、外部ホスト連携のための追加IC・GPIOを前提としない。PSoCはFull-Speed USBデバイス、PCまたはRaspberry PiがUSBホストになる。「USBホストモード」は外部ホストがゲームを主導する動作を指し、PSoCをUSBホストとして動作させる意味ではない。

| 動作モード（構想） | 外部ホスト | ARM | SFC |
|---|---|---|---|
| ネイティブ | 不要 | ゲーム処理・演算 | ゲーム処理・映像・音源・入力 |
| USBホスト駆動 | ゲーム・描画・音源データ生成 | USB・FIFO・データ変換 | PPU・APU制御・入力 |
| ハイブリッド | ゲーム処理・高度な演算・ネットワーク等 | ゲーム処理・展開・変換 | ゲーム処理・映像・音源・入力 |

USBホスト駆動時はNORに格納したSFC側制御プログラムを動作させ、ARM側の共通BIOSまたは専用通信プログラムが外部ホストと通信する。実行中にROMを書き換えず、画像・音源・制御命令を受信し、コントローラ状態・実行結果・デバッグ情報を返送する。ネイティブ動作をUSB接続必須に変更しない。

USBのBulk IN/OUTを候補とし、内部SRAMのリングバッファ、USBエンドポイントとUDB FIFOの間のDMA、ARMによるプロトコル処理を組み合わせる。コマンド、データ種別、転送長、応答、フレーム番号、フロー制御、エラー復旧、接続断時の動作を定義する。具体的なエンドポイント構成、バッファ配分、DMAチャネル数、ゲームABIとの共存は未確定である。通信帯域と転送方法は[communication.md](communication.md)を参照する。

USBホスト駆動機能は現行回路の応用であり、実装・動作確認済みの機能ではない。

## ROM展開と追加音声ドライバ

ゲームローダはROM容量とゲーム固有のミラー規則を判定し、SFCから観測される全ROMアドレスに対して正しいデータが返るようNORイメージを事前に配置する。形式はHiROM、ExHiROM、LoROM、ExLoROMの4種類とし、CPLD側MODE_HILO/CFGと一致させる。NORキャッシュ再利用、消去セクタ・書込みバッファの最適化を行う。

追加モノラル音声ドライバはPSoC内蔵DVDAC、タイマー、DMA、内部SRAMのサンプルバッファで構成する。初期評価は10bit・32kHz PCM、12bitは低帯域で評価する。外部音声入力のアナログレベル、起動/停止時のポップノイズ、DMA負荷は実機で測定する。SPC700とS-DSPの標準音声機能は維持する。[audio.md](audio.md)参照。
