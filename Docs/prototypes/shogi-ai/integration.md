# 森田将棋2側の改造範囲とSFCBuilder接続設計

作成日: 2026-11-17 / 状態: 実装前の提案

## 1. 設計の原則

『早指し二段 森田将棋2』を画面・操作・音源のフロントエンドとして利用する。ST018のコマンドセットや通信タイミングを丸ごと再実装せず、**65C816側ROM中の思考エンジン呼び出し境界**を直接パッチする。呼び出し元が期待するレジスタ、スタック、戻り値、フラグ、メモリ内容を維持できれば、その他のゲームロジックへの変更を減らせる。

対象の通信処理が単一ルーチンとは限らないため、初めに実ROMの実行トレースから全呼び出し箇所、盤面形式、ST018依存の処理範囲を特定する。ここでは既知のアドレスや既存実装を断定していない。

## 2. 改造箇所の調査

| 調査対象 | 確認事項 | 成果物 |
|---|---|---|
| ROM形式 | LoROMの配置、バンク参照、ベクタ、ヘッダ、チェックサム | 原本ハッシュと変換マップ |
| ST018関連 | MMIOアクセス箇所、呼び出し元、初期化・対局・中断処理 | フック位置一覧 |
| 盤面形式 | 81マス、持ち駒、手番、成り、指し手表現、合法手判定の担当 | 型定義と変換関数 |
| 呼出し規約 | A/X/Y・DBR・D・P・スタックの保存規則、戻り値 | 通信ドライバABI |
| 表示・音声 | 思考待ち表示、BGM、割り込み、ROM参照箇所 | WRAM実行可能コードの範囲 |
| 動作モード | 難易度、時間制限、中断、投了、詰み通知 | 必要なコマンド一覧 |

65C816コードの改造単位は、元のルーチンと同一の入出力を持つ薄いラッパーにする。ラッパーからSFCBuilder専用のプロトコルを呼び、可能な限り既存の局面管理・UI処理に手を加えない。

## 3. 推奨する論理API

以下の値はこの実証プログラム専用の**暫定コマンド番号**であり、SFCBuilder本体の標準レジスタ定義ではない。

| コマンド案 | 意味 | 主なデータ |
|---|---|---|
| `AI_INIT` (0x01) | AIの初期化 | プロトコル版数 |
| `AI_SET_POSITION` (0x02) | 初期局面設定・局面の同期 | 盤面、持ち駒、手番 |
| `AI_MAKE_MOVE` (0x03) | 対局者の着手を通知 | 移動元、移動先、成り、打ち駒 |
| `AI_SEARCH` (0x04) | 思考開始 | 制限時間、最大探索深度等 |
| `AI_STOP` (0x05) | 思考中断要求 | 要求ID |
| `AI_GET_BESTMOVE` (0x06) | 最善手の取得 | 要求IDと指し手 |
| `AI_GET_SCORE` (0x07) | 評価値の取得 | スコア、探索深度等 |
| `AI_SET_LEVEL` (0x08) | 難易度の設定 | 思考時間・探索設定 |

プロトコルのメッセージ枠には版数、要求ID、コマンド、ペイロード長、ペイロード、結果コードを持たせる。指し手と局面は、元ROMの内部表現とARMエンジンの内部表現の両方から独立した、仕様を文書化したバイナリ形式に変換する。USIを参考にする場合も、通信自体をテキストUSIに固定しない。

## 4. 現行の通信レジスタへの接続

通信の基準アドレスは既存Rev.0.6の `$00:5000` とし、`COMMAND=$5000`、`STATUS=$5001`、`REPLY=$5002`、`BUS_CONTROL=$5003`、`TX_DATA=$5004`、`RX_DATA=$5005`、`FIFO_STATUS=$5006`、`IRQ_CONTROL=$5007`、`IRQ_STATUS=$5008`、`LENGTH_LO/HI=$5009/$500A`、`ERROR=$500B` を利用する。以降の追加機能を無断で予約レジスタへ割り当てない。

- 盤面送信など複数バイトの転送にはTX_DATAと送信長・ハンドシェイクを使用する。FIFOは各方向4バイトなので送信側はFULLを監視し、受信側はEMPTYを監視する。
- COMMANDの送信とSTATUS/REPLYの取得は、現行メールボックスがBUSY解除まで新規書き込みを受け付けないことを考慮する。
- 完了通知は当初ポーリングを使用し、ARM所有中にはSFC IRQが保留される現行仕様に合わせる。バス返却後のIRQ通知は後続段階で評価する。
- タイムアウト、キャンセル、要求ID不一致、FIFOオーバーフロー/アンダーフローの処理をプロトコルで規定する。

## 5. 外部NORをARMが使用する間の処理

```text
[SFC側ROMでUI実行]
  盤面を確定 → ARMへAI_SEARCH要求
    |
    v
[SFC側WRAM常駐ルーチン]
  ROMを使うIRQ/NMI・DMAを停止し、ARMへのバス譲渡に合意
    |
    v
[ARMが外部バスを専有]
  NORからNNUE重みを取得 → 評価・探索
  SFCはWRAMから$5000の通信状態をポーリング
  PPUは保持中の盤面を表示、APUは音楽を再生
    |
    v
[ARMが探索を完了してバス返却]
  結果を通信レジスタ/FIFOで受領
    |
    v
[SFC側で駒を更新して通常のROM実行へ復帰]
```

ここで重要なのは、RAM常駐ルーチンの実行中にゲーム本体のROMを参照する分岐、定数ロード、ライブラリ呼び出し、割り込みベクタ取得が生じないことである。バス所有権切り替えはRev.0.6で定めた隔離状態 `SFC(00) → isolate(01/10) → ARM(11)` と逆方向の手順に従う。SFC本体WRAMは128KiBであり、PSoCの内部SRAMとは別である。

画面演出がROMへのアクセスを必要とする場合は、思考前に必要なコード・表示素材をWRAMやVRAMへ準備する。初期版は盤面を表示したまま待機するだけでよく、思考中の複雑な演出は必須要件にしない。

## 6. ROM変換と配布物

SFCBuilder Rev0.8はCPLDによってLoROMのハードウェアアドレス変換に対応する。したがって原本のROMがLoROMである場合も、原本のバンク配置とROMヘッダ・リセットベクタを基本的に維持したまま起動を検証する。通信部のフック挿入、追加のARM連携コード、拡張ROM容量への移行が必要な場合には対象箇所を個別にパッチし、エミュレータで検証してから実機へ移す。

GitHubに保存するのは逆アセンブル調査のメモ、バイナリ差分パッチ生成器、パッチ適用手順、原本識別ハッシュ、独自実装した通信コードである。**市販ゲームの元ROM、グラフィックス、音声、ST018内蔵コードはリポジトリへ追加しない**。成果物の頒布方法については権利関係を確認したうえで決定する。

## 7. 完了条件

同一の操作手順で、(a)元ゲームの盤面と操作、(b)SFCBuilder通信経由の思考要求、(c)ARMから返却した合法手の画面反映、(d)連続対局および中断・再開が動作することを確認する。SFC側MMIOとCPUレジスタ保存規約についてはデバッガのトレースにより検証する。
