# PSoCを使わない場合 — STM32 + CPLD構成の検討

- 検討日: 2026-11-18
- ステータス: **比較検討案（SFCBuilder Rev.0.6 の確定仕様ではない）**
- 関連資料: [現行ハードウェア](../hardware.md)、[バス制御](../bus-udb.md)、[ピン割り当て](../pinout.csv)、[メモリマップ](../memory.md)、[通信](../communication.md)

## 1. 発端と設計目標

SNES_HX_420のようにマイコンでSFCのROMアクセスそのものをソフトウェア処理すると、数百ns単位のバス応答を継続して保証する必要がある。外部Quad SPI PSRAMもSFCの個々の読み出しに直接応答できないため、内部SRAMの64KiB程度のウィンドウを経由する方式となり、メモリ更新時にSFC側の協調待機が必要になる。

対案として、NOR Flashと非同期SRAMはSFCから通常のカートリッジと同様に直接アクセスできるようにし、STM32をコプロセッサとして独立させ、CPLDを高速なメモリマッピング・チップセレクト・バス制御に限定する。CPUの演算性能をバスのリアルタイムエミュレーションに費やさず、既存SFCソフトとのマッピング互換性を維持することを重視する。

## 2. 基本部品と役割

| 部品 | 役割 |
|---|---|
| パラレルNOR Flash | SFCのプログラム・リソースを直接読み出す（現行構想は8MiB/23bitアドレス） |
| 非同期SRAM | セーブ・ワーク・STM32との共有メモリ（現行構想は128KiB） |
| 5V入力対応CPLD | HiROM/ExHiROM等のアドレス変換、ROM/RAMの選択、/CE・/OE・/WE、バス所有権・通信領域のデコード |
| STM32 | ゲーム演算、SD/USB等の拡張機能、CPLDへの制御信号、必要時の共有メモリ操作 |
| レベル変換IC | SFC 5Vデータバスと3.3Vメモリデータバスの双方向変換 |
| 3-stateバッファ（3SB） | SFC側の一部のアドレス線およびSTM32側アドレス線を共有メモリバスから隔離 |

CPLDの機能はなるべく**組み合わせ論理**とし、4〜8ビット程度の専用制御バスをSTM32 GPIOからCPLDへ直接接続する。制御状態の保持はSTM32のGPIO出力レジスタ側に任せ、CPLD側には大きな制御レジスタやFIFOを作らない。信号のビット割り当ては未確定。

## 3. SFCBuilderの既存ピン分割を転用する

Rev.0.6ではSFCアドレス24本を分け、以下の**14本だけをPSoCに直接入力**し、残り10本は外付け3SBから共通メモリバスに送る。

| 分類 | SFC信号 | 本数 |
|---|---|---:|
| 直接入力 | A0〜A4、A12〜A15、A19〜A23 | 14 |
| 外部3SB経由 | A5〜A11、A16〜A18 | 10 |
| 合計 | A0〜A23 | 24 |

PSoCをCPLDへ置き換える場合もこの分割を流用する。CPLDは必要な14本を受け取り、ROM領域の上位アドレス変換とメモリ制御信号の生成を行う。メモリ側は23bitアドレス・8bitデータの共通バスとし、既存[メモリマップ](../memory.md)のHiROM/ExHiROM、512KiB単位のミラーリング、SRAM固定配線を参考にする。

**重要**: 23本すべてをCPLDの出力にする場合と、10本を3SBでメモリへ直接送る場合は、CPLDの必要出力数が違う。既存PSoC設計では23本すべてのMEM_AをPSoCにも接続するが、SFC所有中の10本はHigh-Zとして3SBが駆動する。CPLD版でも同じ23本のアドレス出力端子を持たせる案を基本比較とし、未使用となる出力・配線の最適化は次段階で検討する。

## 4. 内部バスの所有権と3-state

SFCアクセス中は、CPLDのアドレス変換出力とSFC側3SBが内部メモリアドレスを供給し、STM32は外部メモリを駆動しない。STM32所有時はSFC側3SBおよびCPLDの該当出力をHi-Zにし、STM32がアドレス・データを出す。

| モード | SFC側アドレス3SB | CPLDメモリアドレス出力 | STM32側の出力 | NOR/SRAM |
|---|---|---|---|---|
| SFC所有 | 有効 | 必要なビットのみ有効 | Hi-Z | SFCアクセス |
| 移行・隔離 | Hi-Z | Hi-Z | Hi-Z | CE/OE/WE無効 |
| STM32所有 | Hi-Z | Hi-Z | 有効 | STM32アクセス |

CPLDの各I/Oには3-state出力制御があるためCPLD側のOEは内部で生成できる。反面、STM32のGPIOとCPLDの出力を単純に直結して双方のGPIOモード変更だけに頼る構成は、リセット・ソフトウェア誤設定・切り替え中の衝突で故障リスクがある。STM32側にも**OE付き外付けバッファ／トランシーバ**を設け、ハードウェアで排他的な出力許可と両側Hi-Z期間を保証する方向を優先する。切り替え時にはCE/OE/WEを無効化し、SFCはWRAM上の待機コードからROM/SRAMを参照しない。

STM32側の23bitアドレスを3SBで隔離する場合、16bitのSN74LVC16244A **1個だけでは不足**し、16bit品2個相当が必要になる。SFC側の既存3SBとは別に数える。STM32側の双方向8bitデータバスにも読み書きに応じた適切な方向制御・隔離が必要であり、単方向3SBだけでは完結しない。

## 5. データバスとコプロセッサ通信

SFCデータD0〜D7は5V双方向、NOR/SRAMデータD0〜D7は3.3V双方向なので、DIRと/OEを備える専用8bitレベル変換IC（例: SN74LVC8T245のようなクラス）が必要である。レベル変換ICは双方向の**レベル**を変換するが、内部メモリバスをSFC・STM32のどちらが駆動するかの**所有権制御**も別途必要になる。

- SFC↔メモリの通常転送では、CPLDのデコード結果から変換ICのDIR・/OEを制御する。データ自体をCPLD内部で中継しない構成なら、CPLDの必要I/Oを削減できる。
- STM32↔メモリの読み書きでは、SFC側レベル変換ICを隔離し、STM32側データ経路を有効にする。
- SFCからSTM32へのコマンド書き込みには、SFCアクセスの瞬間に8bitデータを安全に捕捉・保持する回路が必要になる。STM32への単なるアドレス通知だけでは連続書き込みを保証できない。
- SFCから通信レジスタを読む際には、STM32の割り込み応答を待つことはできない。事前に準備した出力データ、少量のハードウェアレジスタ、外付けラッチ、共有RAM等の方法を別途設計する。
- 現行PSoC版の$5000系通信レジスタや各方向4バイトFIFOはUDB内蔵のレジスタ／データパスで実装する計画だが、CPLD＋STM32版にそのまま移植できるとは考えない。機能を削減するか、外付けラッチ／FIFOや別の通信方式を採用する必要がある。

## 6. CPLDの候補とI/O概算

5V系のSFCアドレス・制御入力を直接受ける候補として、Microchip ATF1504AS（64マクロセル、最大64汎用I/O）とATF1508AS（128マクロセル、最大96汎用I/O）を比較した。I/O出力の電圧はVCCIO配線で決まり、5V入力対応と3.3V出力が全ピンで任意に混在できることは同義ではない。パッケージ別のピン割り当て、出力電圧、JTAG兼用端子は正式なデータシートとCADで再確認する。

まずCPLDがSFC 24bit、STM32 23bitの全アドレスを**独立入力**し、メモリ23bitを出力する完全内部MUXは、アドレス系だけで24+23+23=70 I/O、制御8bitを加えると78 I/Oとなり、制御信号／データ系を含めると64 I/O品には収まらない。

一方、既存SFCBuilder型のアドレス分割と3SBを活用する案では、比較用の保守的な概算は次の通り。

| 信号区分 | CPLD I/O概算 |
|---|---:|
| SFCアドレス直接入力 | 14 |
| 共通メモリアドレス出力 | 23 |
| SFCデータ入力／出力（レベル変換後） | 8 |
| 内部メモリデータ入出力 | 8 |
| SFC制御／IRQ等 | 5 |
| メモリ制御 | 4 |
| STM32からの制御バス | 8 |
| アドレス3SBのOE制御 | 2 |
| **合計（仮配置）** | **72** |

この72本は**データバスをCPLDで中継する場合の暫定構成**で、レベル変換ICのDIR/OE、STM32への通信通知・データ経路、JTAG・電源等の割り当ては確定していない。データバスを直接共通化するならCPLDの8bit+8bitのデータ中継は削減できるが、その分、外部の方向制御・ラッチ・バッファが増えうる。

ATF1508ASの100ピン／80 I/O品はこの暫定72本に近く余裕が小さい。128ピン／96 I/O品なら配線上の余地は増える。どちらも実装可能性の確定にはピンアサイン、OE端子、論理合成、遅延検証が必要である。

CPLDには多数のレジスタを置かず、STM32の4〜8bit GPIO制御で固定の組み合わせ論理を切り替える。レジスタやFIFOを増やすとマクロセルと積項の予算が急増するため、基本マッピングとバス制御に絞る。

## 7. コスト・実装難易度の評価

外付けNOR Flash・SRAMはPSoC版と共通だが、STM32+CPLD版ではCPLD本体に加えて5V↔3.3V双方向レベル変換、STM32側のアドレス3SB（23bit分）、必要に応じたデータバス用トランシーバ、制御信号・電源回路の追加を見込む。I/Oの多いCPLDは100ピン以上になり、PCBの面積と配線密度も増える。会話中に挙げたCPLD価格は時点依存の参考例であり、確定BOM単価ではない。

STM32の演算性能や周辺機能（USB High-Speed、SDIO、大容量外部メモリ等）が不可欠なら独立構成を検討できる。一方、SFCBuilderの狙いである低価格・HiROM/ExHiROM互換・ARMコプロセッサ・USB接続については、PSoC 5LPは5V/3.3VのI/Oバンク、24 UDB、192マクロセル相当のPLD、24個の8bitデータパス、Cortex-M3、DMA、USB Full-Speedを単一チップに集積するため、外付け部品と配線を大幅に省ける。

## 8. 現段階の結論

「PSoCを使わない場合」の代替案としては、**NOR Flash + SRAM + CPLD + STM32 + データバス用レベル変換IC + 必要な3SB／トランシーバ**が現実的な候補である。既存SFCBuilderの14bit直接アドレス入力／10bit 3SB構成とメモリマップを流用すれば、全アドレスMUX案よりCPLD I/Oの負担を減らせる。ただし、データバスの双方向制御、通信レジスタへの即時応答、バス所有権移行時の競合防止を外部ハードウェアで再構成する必要がある。

したがって、現行SFCBuilderのPSoC 5LPを変更する決定ではなく、**独立した代替アーキテクチャの検討記録**として保持する。実際の採用判断には、全信号のピン配置、論理合成、バス切り替えと出力許可のタイミング、5V/3.3V電気条件、BOM・PCB試算を必要とする。
