# Rev.0.9 3Dグラフィックス実証計画

更新: 2026-11-20。状態: **採用した映像表示方式の設計目標（未実装・未実機検証）**。AG32VF407VGT6（RV32IMAFC、最大248MHz、CPU内蔵SRAM128KiB）で3D画像を生成し、SFCの65C816がPPUへ転送する。ハードウェア本体Rev.0.9の仕様とピン配置は変更しない。**3DデモとUSB映像転送モードには同一の表示経路を使用する。** 共有SRAM・通信窓・USBとの接続は[SDK・USB連携](../../sdk-emulator.md#カートリッジからsfc本体への映像転送)に従う。

## 1. 採用する表示方式と解像度

**表示目標は152×104の1種類とし、解像度のストレッチ目標は設けない。** SFCのMode 3・BG1（8bpp）だけを使用し、横方向に128画素の通常パレット領域と24画素の動的CGRAM色領域を配置する。通常領域はVRAMへDMAで8bppタイルを書き込み、動的領域は固定タイルの画素番号が参照するCGRAM RGB555をHDMAで更新する。BG1VOFSもHDMAで制御する。

| 項目 | 設計目標 |
|---|---:|
| 論理画像解像度 | **152×104** |
| 通常パレットによるBG1 8bpp画像 | **128×104** |
| 固定画素番号＋動的CGRAM RGB555領域 | **24×104** |
| NTSC標準表示の想定走査線 | 224本/フィールド |
| 強制ブランキング（`$2100 INIDISP`） | 上側8本＋下側8本 |
| 表示に使用する走査線 | **208本/フィールド** |
| 画像1ラインの表示時間 | 4走査線 |
| 1フィールドの新規画像ライン | **52ライン** |
| 偶奇2フィールドの論理画像ライン | **104ライン** |
| 時間方向の目標 | 約60フィールド/秒（完全画像の組は約30組/秒） |
| 通常側の有効画素情報 | **6,656B/フィールド** |
| 通常側の8×8タイル全更新 | **7,168B/フィールド** |
| 動的CGRAMのRGB555色情報 | **2,496B/フィールド** |

**104ラインは偶数・奇数フィールドに52ラインずつ異なる画像情報を与える設計上の論理解像度である。** Mode 3における偶奇フィールドの表示位置、独立した垂直画素として見えるか、行のちらつき・ずれは実機とエミュレータで確認する。毎フィールドの新規画像生成により時間方向で約60Hzの動きを目指すが、60枚/秒の完全なプログレッシブ152×104映像とは扱わない。

## 2. 8bpp BG1・CGRAM配置

Mode 3・BG1は8bppでCGRAMの256エントリを使用する。色番号0を透明として予約し、通常領域と、表示中の色を上書きしないためのA/B二組の動的領域へ配分する。

| CGRAM用途 | エントリ数 | 役割 |
|---|---:|---|
| 透明番号0 | 1 | BG1透明 |
| 通常パレット | **207** | 左128画素で共有するRGB555パレット |
| 動的パレットA | **24** | 右24画素の固定8bpp番号が参照する色 |
| 動的パレットB | **24** | 更新中と表示中を交代する色 |
| 合計 | **256** | `1 + 207 + 24×2` |

通常領域は横16枚、動的領域は横3枚の8×8タイルでちょうど境界が揃う。動的領域は、各画像ラインの24画素に対応したCGRAM A/B番号を参照する**固定8bppタイルパターン**を使用する。A/Bパレットの参照行とBG1垂直スクロールを同期させ、同じ色番号を表示している間はその番号のCGRAMを更新しない。VRAMの動的領域の固定タイルとタイルマップは毎フィールド全面転送する対象に含めない。通常領域も最終的なPPU出力色精度はRGB555である。

## 3. 追加強制ブランキングとVRAM DMA

`$2100 INIDISP`を使用し、標準224走査線の上下8走査線ずつを強制ブランキングし、中央208走査線へ映像を表示する。**通常のV-Blank信号自体が16走査線長くなるわけではなく、描画を停止した表示期間をVRAM書き込みにも使用する**設計である。開始・終了は65C816のHV-IRQなどで走査線同期し、強制ブランキングを表示開始前に解除、表示終了後に再設定する制御を検証する。

1フィールドの有効画素は`128×52 = 6,656B`。BG1の8bppタイルは8×8×1B＝64B/枚なので、横16タイル、縦52画像ラインを含む7タイル行の全更新は`16×7×64 = 7,168B`となる。最下段4画像ラインは表示対象外のタイル行領域として扱い、**全更新のDMA計画は7,168Bを基準**とする。転送にはVRAMアドレス設定・DMAレジスタ設定・HDMAとのチャネル競合・その他PPU更新の時間が別途必要になる。

NTSCで通常のV-Blankを約37走査線と見積もり、1走査線1364マスタークロック、DRAMリフレッシュ40クロック、DMA 8クロック/Bとすると、強制ブランキングを含む53走査線の理論枠は`(37+16)×(1364-40)/8 = 8,771.5B`相当である。この値は**DMA実効容量でも転送完了保証でもない**。上8走査線・下8走査線と通常V-Blankは非連続であり、DMA設定や割込みのコスト、HDMAの停止・再初期化、外部SRAM応答を含む走査線単位のスケジュールが必要となる。

SFCの通常DMAとHDMAは同じ8チャネルを共有する。可視208走査線では8チャネルのHDMAを使用するため、追加強制ブランキング中に通常DMAを行う場合は、チャネルの無効化・初期化・再開時点を明示して安全に調停する。上側のDMA利用を省く場合、下側8走査線＋通常V-Blank45走査線の理論枠は約7,447.5Bで、7,168Bとの差は約279.5Bにとどまる。**上下のブランキングをどう利用するかを含めて実装検証し、理論枠をそのまま利用可能とは見なさない。**

## 4. H-Blank CGRAM・BG1VOFS HDMA

中央208走査線を4走査線単位で52画像ラインへ割り当てる。非表示側のCGRAMパレット24色を1走査線につき6色ずつ、4走査線かけて更新し、次の画像ラインで表示用パレットA/Bを交代する。

| HDMAチャネル | PPUレジスタ | 転送モード | 1走査線の転送 |
|---|---|---:|---:|
| CH0 | `$2121` CGADD | 0 | 開始色番号1B |
| CH1～CH6 | `$2122` CGDATA | 2 | RGB555を各1色（各2B、計12B） |
| CH7 | `$210E` BG1VOFS | 2 | 垂直スクロール2B |
| 合計 | | | **15B/走査線** |

CH0が更新対象A/Bパレットの先頭アドレスを指定し、CH1～CH6が`$2122`へ各2バイトを書き込む。CGRAMのアドレス自動増加を利用して**連続6色／走査線**を更新する。4走査線で`6×4 = 24色`となる。表示中のパレットに書き込まないA/B切替は固定8bppタイルの画素番号配置で表し、BG1VOFSを各走査線で補正して同一画像ラインを4走査線にわたって参照する。

1フィールドのCGRAM色情報は`24×52×2 = 2,496B`。走査線あたりCGADD 1BとBG1VOFS 2Bも必要なので、HDMAのPPUレジスタ転送データ総量は`15×208 = 3,120B`（CGRAM色2,496B＋CGADD208B＋BG1VOFS416B）となる。HDMAテーブルの行数カウンタ、再読み込み、開始時のパレット初期化は別途扱う。

HDMAの基本時間式`18 + 8×有効チャネル数 + 8×転送バイト数`では`18 + 8×8 + 8×15 = 202`マスタークロック/走査線が基準値となる。**これはHDMAテーブル再読み込みの追加時間・CGRAMアクセス可能な実クロック位置を含む保証値ではない。** CH0→CH1～CH6の順序、`$2121/$2122`の動作、CGRAM A/Bの更新完了前に参照が発生しないことを測定する。

Mode 3ではMode 5/6のような背景垂直画素の自動倍解像度動作を前提にしない。偶奇フィールドの参照行・BG1VOFS・CGRAM A/B番号・実表示位置を合わせた測定が必要である。

## 5. RISC-VからSFCまでのデータ経路

1. RISC-Vは内蔵SRAMを使用して頂点変換、投影、クリッピング、ポリゴン描画、Zテスト、テクスチャ参照などを行い、偶奇フィールド用の画像を生成する。
2. 左128画素は207色の共通パレットへ量子化し、65C816がVRAMへDMAできる8×8・8bppビットプレーンタイルに変換する。右24画素は1画像ラインごとのRGB555 24色として並べ、CH0～CH6のHDMAテーブルと、BG1VOFS用CH7テーブルを生成する。
3. RISC-VはFPGA/AHB・MEM所有権調停を通じて共有外部SRAMへ完成済み転送素材を配置する。65C816は通信窓/FIFO/IRQの準備完了通知に基づいて、強制ブランキング／通常V-Blank内でVRAM DMAを行い、可視期間にはHDMAを使う。
4. バッファ所有権、DMA完了、HDMAテーブル、CGRAM A/B参照、偶奇フィールド位相を同期し、書き込み途中のデータがPPUへ渡らないようにする。通常DMA・HDMAによる同一チャネルの同時使用を避ける。

152×104リニア画像の容量は8bitで`152×104 = 15,808B`、RGB555または16bit Zバッファで各`31,616B`。内蔵SRAM128KiBには実行コード・スタック・頂点・テクスチャ等も必要なので、フレームバッファの同時保持数と実装配置を測定して決める。共有外部SRAM128KiBの末尾8KiBはSFC BIOS用であり、転送素材には残りの領域を使用する。

## 6. 検証手順と合格条件

| 段階 | 実施・測定項目 |
|---|---|
| P0 | CH0のCGADDとCH1～CH6のCGDATAで6色/走査線を正しいアドレスに更新できることを、PPUの書込み可能時刻とともに測定 |
| P1 | CH7のBG1VOFSを併用し、8チャネルで4走査線ごとにCGRAM A/Bを切り替え、24画素/画像ラインが正常表示されることを確認 |
| P2 | 上下8走査線の`$2100`強制ブランキングをHV-IRQ等で制御し、HDMAチャネル初期化・通常DMAとの排他を含む走査線ごとのスケジュールを確定 |
| P3 | 7,168B/フィールドのVRAM DMAを完了し、表示中のVRAM/CGRAM・映像の欠け・色混在が発生しないことを測定 |
| P4 | Mode 3の偶奇52＋52ラインが論理104ラインとして独立した位置に表示されること、フィールド位相、ちらつき、約60フィールド/秒の継続性を確認 |
| R0 | AG32上のレンダリング・Zテスト・207色量子化・24色RGB555変換・タイル化の処理時間と内蔵SRAM消費量を測定 |
| R1 | FPGA共有MEM調停、通信窓/FIFO/IRQ、USB受信モードとの共通転送経路を含めてフィールド連続更新を検証 |

合格判定では、VRAM転送バイト数と完了時刻、CGRAM更新成功数、HDMAテーブル再読み込み、65C816のDMA/HDMA占有時間、実表示される独立画像ライン数、完全画像の更新レート、RISC-V描画FPS、共有MEM待機、FPGA LUT/FF使用量を別々に記録する。**設計採用は実装完了を意味せず、152×104での映像出力達成はP0～P4の検証結果で判定する。**
