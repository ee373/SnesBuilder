# Rev.0.9 SDK・エミュレータ・USB連携

SFC側はPVSnesLibで65C816 HiROM/SlowROM最小サンプルを起動し、RISC-V側はVS Code＋AgRV SDK、FPGA側はPrepare LOGIC＋Supra Nativeを使う。SFCBuilder SDKは$5000通信の64アドレス窓、FIFO/IRQ、コプロセッサ演算、SRAM、メモリ所有権、NORローダをAPI化する。ares/bsnes/Snes9x等のエミュレータはROM4形式・容量ミラー・SRAM・通信・演算要求のゲームから見える挙動を再現する。

USB Full-SpeedではAG32をデバイス、PC/Raspberry Piをホストとし、画像・音声・操作・デバッグを双方向転送する。USBが接続されなくても通常ROMを起動可能とする。

## カートリッジからSFC本体への映像転送

**3DデモとUSB映像転送モードは、SFC側の映像表示・転送方式を共通化する。** 採用する表示目標は[3Dデモ仕様](prototypes/3d-demo/README.md)に定義した**152×104のMode 3・BG1 8bpp統一方式**で、解像度のストレッチ目標は設けない。横128画素はVRAMの8bppタイルをDMA更新し、横24画素は固定画素番号が参照するCGRAM RGB555をHDMA更新する。上下各8走査線の強制ブランキングを追加DMAに利用する設計とし、表示する208走査線はBG1VOFS HDMAで4走査線当たり1画像ラインを参照する。

```text
[カートリッジ側]
  3Dデモ: RISC-Vレンダリング ─┐
                               ├→ 128px 8bppタイル＋24px RGB555/HDMA素材
  USB映像: PC等 → USB → AG32 ─┘
                                        ↓
                               FPGA AHB・共有MEM調停
                                        ↓
                                   外部共有SRAM
                                        ↓ SFCカートリッジバス
[SFC本体]                          65C816
                              ┌─────────┴────────────┐
                              ↓                      ↓
                 強制ブランク＋V-Blank DMA      H-Blank HDMA
                              ↓                      ↓
                         VRAMの8bppタイル      CGRAM＋BG1VOFS
                              └─────────┬────────────┘
                                        ↓
                                      PPU表示
```

RISC-V/FPGAやUSBコントローラからSFCのVRAM/CGRAMへ直接書き込む構成ではなく、**65C816が共有SRAMからDMA/HDMAでPPUへ転送する**。画像本体・DMA/HDMA素材は共有SRAMに配置し、`$5000`の64アドレス通信窓・FIFO・IRQはコマンド、素材完成、フィールド同期、エラーなどの制御通知に使用する。初期各4バイトのFIFOは画像フレームバッファとして扱わない。共通MEM所有権とDMA/HDMAチャネル調停は[bus.md](bus.md)、通信仕様は[communication.md](communication.md)に従う。

### 採用する映像形式とフィールドごとのデータ量

| 項目 | 設計目標 |
|---|---:|
| 論理解像度 | **152×104** |
| BG1 8bpp通常領域 | **128×104** |
| BG1動的CGRAM色領域 | **24×104** |
| 追加強制ブランキング | 上側8＋下側8走査線 |
| 表示走査線 | 208走査線/フィールド |
| 論理画像ライン | 52ライン/フィールド、偶奇2フィールドで104ライン |
| 通常8bpp領域の有効画素情報 | 6,656B/フィールド |
| 8bppタイルの7行全更新DMA量 | **7,168B/フィールド** |
| CGRAM RGB555色情報 | **2,496B/フィールド** |
| HDMAレジスタ転送データ | 3,120B/フィールド（色・CGADD・BG1VOFSの合計） |
| CGRAM | 透明1＋通常207＋動的24×2＝256エントリ |
| HDMA | CH0: CGADD 1B、CH1～6: CGDATA各2B、CH7: BG1VOFS 2B/走査線 |
| 更新目標 | NTSC約60フィールド/秒、完全画像1組は偶奇2フィールド |

通常領域は16タイル幅、動的領域は3タイル幅で構成する。可視期間にはHDMA 8チャネルを使い、CGRAMは6色/走査線を4走査線かけて24色更新し、A/Bパレットを交互に表示する。上下の強制ブランキングは`$2100 INIDISP`で制御するが、V-Blank信号の期間そのものは変更しない。8チャネルを使用するHDMAと通常DMAはチャネルを共有するため、追加ブランキングでのDMA実行、HDMA初期化・停止・再開を含む転送スケジュールは未検証である。Mode 3の偶奇52＋52ラインが独立した104ラインに見えるかも検証対象とする。

### USB映像転送モードの処理順

1. PC/Raspberry Pi側で入力映像の取得・スケーリング・フレーム時刻管理を行い、AG32へUSB Full-Speedで送信する。USB上の画素符号化・圧縮方式・転送パケット・制御プロトコルは実装時に決定する。
2. ホスト側またはAG32側で、128画素幅の8bppタイルビットプレーン、24画素幅の画像ライン別RGB555、CGRAM A/B用CGADD・CGDATAとBG1VOFSのHDMAテーブルに変換する。変換の実行場所はUSB負荷・内蔵SRAM使用量を実測して決める。
3. RISC-Vが共有SRAMへ完成した素材を配置し、FPGAが共通MEMの所有権を調停する。65C816は準備完了通知を受けて強制ブランキングと通常V-Blankの利用可能な期間にVRAM DMAを実行し、可視期間にHDMAでCGRAM/BG1VOFSを更新する。
4. フィールド境界で素材・HDMAテーブル・CGRAM A/B参照・バッファ所有権・DMA完了を同期し、未完成素材を表示しない。USB受信が遅れた場合は完成済みフィールドを保持する。

1フィールドの有効画像情報量は`128×52 + 24×52×2 = 9,152B`であり、60フィールド/秒では`549,120B/s`となる（USBのヘッダ・制御情報・パディングは別）。USB Full-Speedの12Mbit/sは物理ビットレートであり、SFC側のPPU書込み帯域と同一ではない。USB受信速度だけでなく、共有MEM待機、DMA完了時刻、CGRAMの正常更新数、フィールド位相、表示遅延を測定する。

## ゲーム固有RISC-VプログラムとFPGA演算器

SFCBuilderの共通ファームウェアはAG32内蔵Flashに常駐し、ゲームパッケージのRISC-Vコードは外部8MiB NORから内蔵SRAMへ展開して実行する。ゲーム用GCCリンクは内蔵SRAMを実行アドレスとし、共通Flash側のRAM領域と重複させない。共通ファームウェアのサービスは固定ABI/API経由で利用し、SFC側の65C816コードは既存の$5000通信窓とFIFO/IRQを通じてRISC-V側へ処理を要求する。

RISC-VがFPGA内の演算アクセラレータを使う場合は、内部AHBにメモリマップした入力・制御・状態・結果レジスタをMMIO経由で操作する。演算器のアドレスは生成トップで確定する。ゲームパッケージには65C816 ROM・RISC-V実行イメージ・リソース・セーブ定義の配置情報を持たせ、NOR物理容量8MiBの範囲内で格納する。
