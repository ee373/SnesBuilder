# Rev.0.9 3Dグラフィックス実証計画

作成: 2026-11-20。状態: **デモ構想・性能目標（未実装・未測定）**。本ドキュメントは既存のRev.0.9ハードウェア仕様を変更せず、AG32VF407VGT6への移行によって改善された演算能力を評価するためのデモ計画を定義する。

## 1. 目的とRev.0.9での改善

旧PSoC 5LPのCortex-M3（最大80MHz）からAG32のRV32IMAFC（最大248MHz）へ移行したため、CPUの公称最大クロック比は約3.1倍となった。加えてAG32は単精度FPUとCPU内蔵SRAM128KiBを備える。これにより、頂点座標変換、投影、クリッピング、ポリゴン塗りつぶし、深度判定、テクスチャ処理をRISC-V側で実行する構成を検討する。クロック比と実描画FPSを同一視せず、CPU描画時間・共有メモリ書込み・SFC側転送・表示まで個別に測定する。

SFC側の65C816はVRAMへのDMA転送、PPUの設定、BG・スプライトとの合成、入力管理を受け持ち、3Dフレームの演算とソフトウェアラスタライズはRISC-Vで担当する。通常のROM応答を維持するFPGAのメモリ制御が先行必須である。

## 2. 段階的な描画目標

| 段階 | 描画領域 | 試験目標 | 内容 |
|---|---|---|---|
| G0 | 96×80 | 20～30 FPS | フラットシェーディング、簡単なポリゴン、深度処理の基準測定 |
| G1 | 128×96 | 20～30 FPS | 本命候補。Zバッファ、クリッピング、簡易テクスチャ、SFCへの分割転送 |
| G2 | 160×120 | 15～20 FPS | ストレッチ。テクスチャ付きシーン、画面更新と演算処理の最適化 |

上記のFPSは**実験時の目標**であり、達成見込みや保証値ではない。ポリゴン数、画面占有率、画素処理数、テクスチャ帯域、VRAM更新周期と合わせて評価し、描画負荷を固定した比較を行う。

SFCの4bppタイルデータ量（タイルマップ・パレット転送等は別途）は次の通り。

| 描画領域 | 4bppタイル画素データ | 8bitリニア描画バッファ | 16bit Zバッファ |
|---|---:|---:|---:|
| 96×80 | 3,840 B | 7,680 B | 15,360 B |
| 128×96 | 6,144 B | 12,288 B | 24,576 B |
| 160×120 | 9,600 B | 19,200 B | 38,400 B |

128×96の例では、8bitリニア描画バッファと16bit Zバッファで計36KiBとなる。内蔵SRAM128KiBには実行コード、スタック、テーブル、頂点・描画データも必要であるため、全領域を描画用に使用できるわけではない。前後バッファの配置は実際のメモリ使用量から決定する。

## 3. 描画からSFC表示までの経路

1. RISC-Vが内蔵SRAMを中心にモデル変換、投影、クリッピング、ラスタライズ、Zテストを実行する。初期は8bit相当のリニア描画表現を候補とし、最終表示は4bpp等のSFC BG形式へ変換する。
2. SFCの8×8タイル・ビットプレーン配置へ変換し、必要な画素データを外部SRAMの共有領域へ書き込む。RISC-Vから外部SRAMへの書込みはFPGAのAHBメモリコントローラと[共有MEM所有権制御](../../bus.md)に従い、SFCと同時駆動しない。
3. SFC側65C816が共有SRAMをROM/SRAMマッピング上の読出し可能領域として参照し、VBlankでDMAを使用してPPUのVRAMへ転送する。可視フレームの切替はSFC側で管理する。タイルマップを固定化すれば毎フレームの転送対象を主としてタイル画素データへ限定できる。
4. VBlankに収まらない転送量は複数VBlankへ分割する。画面の部分更新、バッファ切替、パレット/タイルマップ更新、SFC側CPU処理時間を含む実スケジュールを確認する。VRAMへカートリッジ側RISC-Vが直接書き込める構成ではない。

4bppで128×96の全画素を更新すると6,144Bが必要であり、NTSCの通常VBlankだけで毎フレーム安定して転送できると想定しない。96×80の3,840BもDMA設定や別のPPU更新処理を含めて検証する。複数VBlankでの転送では、表示更新FPSとRISC-Vの描画FPSを別々に扱う。

## 4. 追加のFPGAアクセラレータ候補

- 初期実装はRISC-V単独描画とし、FPU／整数演算による座標変換・ラスタライズの性能を基準化する。
- [ロードマップのINT16×4ドット積MAC](../../roadmap.md)は4×4行列の4要素内積へ転用可能だが、既存FPGAのROMデコード・AHB・FIFO・メモリ調停に必要な資源を優先する。CPU→FPGAの32bit AHB転送を含めた性能がCPU単独の計算を上回る場合に限って採用を検討する。
- 4bppタイル／ビットプレーンへの形式変換回路も別のストレッチ候補とする。LUT・FF使用量、AHBデータ転送の費用、変換遅延を合成と実測で評価し、最初から追加ハードウェア前提にはしない。

## 5. 実証手順と測定項目

| 工程 | 検証内容 |
|---|---|
| G0-1 | RISC-V内蔵SRAMで固定ポリゴンの座標変換・塗りつぶし・Zテストを実装し、演算時間を計測 |
| G0-2 | 線形描画データからSFCの4bppタイル形式を作成し、画素一致と変換時間を検証 |
| G0-3 | FPGAのAHB経由で外部SRAMへ描画結果を転送し、バス所有権・転送帯域・SFC待機時間を計測 |
| G0-4 | SFC DMAでVRAMへ表示し、フレーム欠落・ちらつき・VBlank消費量を測定 |
| G1 | 128×96でクリッピング・Zバッファ・簡易テクスチャを追加し、20～30FPSを試験 |
| G2 | 160×120と複雑なシーンを試験し、画面更新と演算のどちらが制約か分析 |
| 任意 | INT16×4 MAC／タイル変換のFPGA化とCPU単独処理を同条件で比較 |

主要指標は描画FPS、実表示FPS、1フレーム演算時間、頂点数・三角形数、塗りつぶし画素数、VRAM転送バイト数・所要時間、AHB・共有SRAM待機時間、CPU内蔵SRAM使用量、FPGA使用LUT/FFとする。実装は[SDK・エミュレータ構想](../../sdk-emulator.md)と整合させる。

本デモは本体Rev.0.9のブート・ROMマッピング・通信・共通MEMバスが安定した後に実施し、実測結果が得られるまで解像度/FPSを達成済み仕様として扱わない。
