# 外部メモリとHiROM・ExHiROMマッピング

Rev.0.7 / 基本設計段階

## 1. NORフラッシュ

| 項目 | 仕様 |
|---|---|
| 型番 | S29GL064S70TFI023 |
| 種類 | 非同期パラレルNOR Flash |
| 容量 | 64Mbit（8MiB） |
| データ幅 | 8bitモード |
| 論理バイトアドレス | 23bit |
| 動作電圧 | 2.7～3.6V |
| ランダムアクセス | 70ns |
| ページアクセス | 15ns |
| ページサイズ | 16バイト |
| 書き込みバッファ | 最大256バイト（会話時の選定仕様） |
| パッケージ | TSOP-56 |
| 消去セクタ | 64KiB均一（モデル02） |

BYTE#、DQ15/A-1を含む論理アドレスと実ピンの対応は回路図作成時に確認する。

NORには65C816用ゲームプログラム、ARM用ゲームプログラム、画像、音源、マップ等のリソースを格納する。SFC側起動BIOSはPSoC内蔵Flashに保存し、起動時に外部SRAMへ展開するため、NORにはBIOS専用領域を設けない。SFCはNORから直接実行する。ARMコードはNORまたはmicroSDから内部SRAMへ展開する。

開発用ではmicroSDからゲームイメージを書き込み、電源切断後も内容を保持する。同じゲームのキャッシュが残っている場合は識別情報を確認し、消去・書き込みを省略する。

NORの全8MiBをゲームイメージに使用できる構成とする。BIOS起動時はUDBでSRAM末尾の起動用ウィンドウをSFC側ROM空間に一時マッピングし、通常ゲーム起動時はNORのHiROM/ExHiROMマッピングに復帰させる。

16バイトページ内で必要な制御信号条件を維持できる場合は15nsのページアクセスを利用する。/CEは先行選択、/OEは/RDに応じて制御する。70ns品を維持する。tACC/tCEは最大70ns、tOE/tPACC/tDFは最大15ns（規定電圧・負荷条件）。

## 2. SRAM

| 項目 | 仕様 |
|---|---|
| 型番 | CY62128EV30LL-45SXI |
| 種類 | 低消費電力非同期SRAM |
| 容量 | 1Mbit（128KiB） |
| 構成 | 128K×8bit |
| アクセス | 45ns |
| 動作電圧 | 2.2～3.6V |
| データ保持電圧 | 最小1.5V |
| データ保持電流 | 最大3µA（会話時の選定仕様） |
| チップイネーブル | /CE1、CE2 |
| パッケージ | SOIC-32 |
| tAA / tACE | 最大45ns |
| tDOE / tHZOE | 最大22ns / 18ns |
| tWC / tPWE / tSD | 最小45ns / 35ns / 25ns |

SFCとARMが共有するセーブデータ、ゲーム状態、画像、座標、演算結果、展開済みリソース、転送バッファに使用する。末尾8KiB（物理0x1E000～0x1FFFF）を起動時のBIOS展開領域とし、ここは電源投入・BIOS再起動時に上書きされるため永続セーブ領域には使用しない。通常ゲーム起動後は作業RAMとして利用できる。セーブ用途は先頭120KiB、作業用途は全128KiBを対象とする。セーブ領域と作業領域はゲームパッケージまたはSDKから指定する想定とする。CR2032によるデータ保持回路は[power-cic.md](power-cic.md)を参照する。

## 3. ROMアドレス変換とハードウェアミラーリング（Rev.0.7）

8MiB NORをHiROM（1～4MiB）またはExHiROM（1～8MiB）としてマッピングする。ROM容量は1MiB単位で設定し、3bitのROM_BLOCKS_M1を「有効1MiBブロック数−1」とする。ROMに選択されている場合のみ変換を適用する。

| SFC側 | NOR論理アドレス | 経路 |
|---|---|---|
| A0～A4、A12～A15 | 同番号 | PSoC |
| A5～A11、A16～A18 | 同番号 | 外部3SB |
| **A19** | **同番号で無変換** | **外部3SB未使用CH→MEM A19（P1[5]）** |
| A20～A21 | 容量別変換してMEM A20～A21 | PSoC |
| A22 | ROMデコードに使用、ROM上位生成には未使用 | PSoC |
| A23 | 反転してMEM A22を生成（HiROMでは0） | PSoC |

```verilog
wire [2:0] x = {~sfc_a23 & exhirom_enable, sfc_a21, sfc_a20};
wire [2:0] n = rom_blocks_m1; // 1MiB blocks - 1
wire [2:0] y;
assign y[2] = x[2] & n[2];
assign y[1] = x[1] & (n[1] | (n[2] & ~x[2]));
assign y[0] = x[0] & (n[0] | (n[1] & ~x[1]) | (n[2] & ~x[2]));
assign mem_a19 = sfc_a19_via_3sb; // host mode; ARM mode uses GPIO P1[5]
assign mem_a20 = y[0];
assign mem_a21 = y[1];
assign mem_a22 = y[2];
```

HiROMではROM_BLOCKS_M1=0～3、ExHiROMでは0～7を有効とする。容量の非2冪ミラーは、3MiBなら0,1,2,2、6MiBなら0,1,2,3,4,5,4,5の1MiBブロック列になる。SRAMはMEM A19をSRAM A16として利用するため、無変換のA19を維持する。SFC所有時は3SBがMEM A19を駆動し、ARM所有時は3SBをHigh-ZにしてPSoC P1[5]をGPIO駆動する。アドレス変換はROM選択時のみ有効とする。

1MiB未満のROMはゲームローダが元データを複製・配置して物理NORの1MiBイメージへ変換する。1MiB以上で整数MiBの容量は必要なブロックだけ書き込み、ハードウェアミラーリングを使用する。1.5MiBなど整数MiB以外の容量は、元カートリッジのミラー規則に従い1MiB境界へソフトウェア補完する。非2冪容量の単純な末尾パディングでは互換動作を保証しない。

書き込み時間の参考試算では、256バイトバッファプログラム典型400µs、64KiBセクタ消去典型300ms、逐次消去を仮定すると512KiBが約3.22秒、1MiBが約6.44秒。差は約3.22秒（microSD読み込み、照合、コマンドオーバーヘッドは除外）。複数セクタ消去や書込み内容により変化するため、実機ローダで計測する。

論理式と独立モデルの384条件照合はPASS。HDLシミュレータの実行、PSoC Creator配置・STA、SRAM/ARMを含む総合検証は未実施。[verilog/README.md](verilog/README.md)参照。

## 4. SFC側のメモリ領域

| バンク | アドレス | 用途 |
|---|---|---|
| $00～$3F | $8000～$FFFF | ROM後半 |
| $40～$7D | $0000～$FFFF | ROM後半 |
| $7E～$7F | $0000～$FFFF | 本体WRAM |
| $80～$BF | $8000～$FFFF | ROM前半 |
| $C0～$FF | $0000～$FFFF | ROM前半 |
| $00～$3F、$80～$BF | $5000～$5FFF | ARM通信（extension_enable時） |
| $20～$3F、$A0～$BF | $6000～$7FFF | HiROM型SRAM（hi_enable時） |
| $80～$BF | $6000～$7FFF | ExHiROM型SRAM（ex_enable時） |

SRAMの2モードは独立に設定できる。新規ゲームでは両方を有効化可能とし、従来ROMでは対象基板に合わせて選択する。両方有効時は$20～$3F、$80～$BFの各$6000～$7FFFがSRAMとなる。SRAM選択条件はROMマッピングとは独立させる。上表のROM前半・後半はExHiROM（未縮小設定）の場合であり、HiROMではA22を0に固定して前半4MiBへ対応させる。通信拡張は既存ROM実行時に無効化可能とする。

8MiB ExHiROM設定ではSFCから直接参照できる物理容量は7.9375MiB（8MiB−64KiB）であり、$7E0000～$7E7FFF、$7F0000～$7F7FFFはARMからのみ直接参照できる。ExHiROMヘッダは物理$40FFC0、CPU $00:FFC0に配置する。リセットベクタも同じ変換を考慮する。

通信領域はA0～A4のみを個別にデコードするため、32アドレスが32バイト単位・各システムバンクにミラーされる。正式なSDKベースは$00:5000。

## 5. SRAMアドレス変換

SRAMは8KiBのウィンドウ16個で128KiBを扱う固定配線とする。

| SRAM側 | 共通メモリバス |
|---|---|
| A0～A12 | A0～A12 |
| A13 | A16 |
| A14 | A17 |
| A15 | A18 |
| A16 | A19 |

ARM側はソフトウェアでバイトアドレスを変換する。

```c
uint32_t sram_bus_address(uint32_t addr)
{
    return (addr & 0x1FFF)
         | ((addr & 0x1E000) << 3);
}
```

下位13bitは連続しているため、8KiB内は連続アドレスとして扱える。8KiB境界で変換後の上位アドレスを更新する。

ROM・SRAM・独自レジスタの排他的なデコードは[bus-udb.md](bus-udb.md)に定義する。SRAMの上位アドレスはバンク番号下位4bitから生成されるため、16バンクごとに同一物理SRAMを参照する。既存ゲーム向けに小容量SRAMのミラーが必要な場合はソフトウェア変換・個別パッチで対応する。

## 起動BIOS用の6バイト・ブートROM（2026-11-18採用方針）

SRAM末尾8KiB（物理0x1E000～0x1FFFF）は変更しない。PSoC内蔵Flashからこの領域へBIOS本体を展開する。SFCのリセットベクタがあるCPUバンク$00をSRAM末尾へ直接ミラーする方式は採用せず、BOOT_MODE中の限定的なROM読み出しをUDBの固定値応答へ差し替える。

| SFC CPUアドレス | UDBが返す値 | 意味 |
|---|---|---|
| $00:FFFC | $00 | リセットベクタ下位 |
| $00:FFFD | $80 | リセットベクタ上位（$8000） |
| $00:8000 | $5C | JML opcode |
| $00:8001 | $00 | ジャンプ先下位 |
| $00:8002 | $60 | ジャンプ先中位 |
| $00:8003 | $2F | ジャンプ先バンク |

リセット解除後、SFC CPUは$00:8000の `JML $2F6000` を実行する。HiROM型SRAMのバンク$2F:$6000～$7FFFは既存配線により物理0x1E000～0x1FFFFへ対応し、A19は3SB経由のまま固定配線で届く。起動時にHiROM SRAMデコードを有効にし、$2FのROM窓はブート固定値応答の対象に含めない。UDBのROM側出力許可をBOOT_MODEかつ対象アドレスのみに限定し、同じサイクルでNOR /CEを無効化してデータバス競合を防ぐ。BOOT_MODE中の他のROM空間の読出しは、BIOS側が必要とするまで無効とする。

ブート固定値は既存のSFCデータバス出力経路と共有する組み合わせ論理で実装し、追加GPIO・追加IC・外部ROMは使用しない。SFCが$2F:6000へ到達後、SRAM BIOSが$5000通信レジスタからARMへBOOT_MODE解除を要求し、完了を確認する。解除時にNORを通常マッピングへ戻すが、実行中の$2F:6000～$2F:7FFFのSRAM窓は維持する。起動中は割り込み禁止とし、必要な割り込みベクタ・割り込み処理への移行をBIOS側で管理する。

固定値の6バイトはアドレスごとの応答データ総量であり、追加の物理6バイトROMを意味しない。デコードとMUXのPLD使用量、バンク$00限定条件、アクセス遅延、BOOT_MODE解除の通信順序、NOR非選択条件はPSoC Creatorと実機で検証する。
