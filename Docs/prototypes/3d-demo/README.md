# Rev.0.9 3Dグラフィックス実証計画

更新: 2026-11-20。状態: **採用表示方式の設計目標（未実装・未実機検証）**。AG32VF407VGT6（RV32IMAFC、最大248MHz、内蔵SRAM128KiB）が3D画像を生成し、外部共有SRAM・65C816・PPUを通じて表示する。ハードウェアRev.0.9の配線は変更しない。USB受信映像も同じ表示方式を採用する。画像生成元を含む共通経路は[SDK・USB連携](../../sdk-emulator.md#カートリッジからsfc本体への映像転送)を参照する。

## 1. 表示方式と目標解像度

**Mode 3・BG1 8bpp統一方式、論理152×104（128＋24）、解像度のストレッチ目標なし**を採用する。横128画素は通常のBG1 8bppタイルをVRAMへDMA更新し、横24画素は固定8bppタイルの画素番号が参照するCGRAMのRGB555値をHDMA更新する。標準NTSC 224表示走査線の上下各8走査線は`$2100`の強制ブランキングで非表示とし、中央208走査線を表示する。4表示走査線当たり1画像ラインを参照するため、52画像ライン／フィールド、偶奇2フィールドで104画像ライン相当の情報を扱う。

| 項目 | 採用目標 |
|---|---:|
| 論理画像情報量 | **152×104** |
| 通常BG1 8bpp領域 | **128×104** |
| 動的RGB555領域 | **24×104** |
| 追加強制ブランキング | **上8＋下8走査線** |
| 可視表示領域 | **208走査線** |
| 1画像ラインの表示割当て | **4走査線** |
| 1フィールドの新規画像ライン | **52** |
| 通常8bppの画素データ量 | **6,656 B/field**（128×52） |
| 全タイル更新量 | **7,168 B/field**（16×7×64） |
| 動的RGB555の色情報 | **2,496 B/field**（24×52×2） |
| 表示レートの目標 | NTSC約60フィールド/秒 |

104ラインは2フィールドに52ラインずつ別の情報を与える**論理画像情報量**であり、Mode 3で104本の空間的に独立した画素行を表示できることは実機未検証である。2フィールド1組の完全画像は約30組/秒であり、60fpsの完全なプログレッシブ表示とは異なる。偶奇位相、縦位置、ちらつき、実表示される独立行数を測定する。

## 2. CGRAMの割り当てと固定タイル

BG1は全画面8bppで、CGRAMの256色番号を次のように割り当てる。

| CGRAM番号 | エントリ数 | 用途 |
|---|---:|---|
| 0 | 1 | BG1透明番号 |
| 1～207 | **207** | 通常8bpp共通パレット |
| 208～231 | **24** | 動的RGB555パレットA |
| 232～255 | **24** | 動的RGB555パレットB |

`1+207+24×2=256`。通常画素も最終表示色はRGB555である。動的領域は横8画素×3タイルに一致し、通常領域の128画素とタイル境界が揃う。動的画素番号を固定タイルへ埋め込み、表示行ごとにA/B番号を選択する。表示中の24色は保持し、非表示側24色を次行のためにHDMAで更新する。初回表示行の色は可視期間前に初期化する。

## 3. 強制ブランキングとVRAM転送

上下各8走査線の`$2100`強制ブランキングは、V-Blank信号を延長するのではなく、**描画しない区間を追加してVRAMアクセス可能時間を増やす方式**である。HDMAの8チャネルを表示処理で使うため、強制ブランキング境界はHV-IRQ等による65C816側の制御を検証する。

8bpp画素情報は`128×52=6,656 B`。一方、8×8・8bppタイルは1枚64Bであり、縦52行には7タイル行分が必要なので、全更新では`16列×7行×64B=7,168 B/field`を転送する。タイルデータはSFCのビットプレーン形式へ事前変換する。タイルマップ、固定タイル、DMA設定、PPU設定、HDMAテーブル管理はこの7,168Bに含まない。65C816が共有SRAMからDMAでVRAMへ転送し、RISC-V・FPGAからPPUへ直接書き込まない。

NTSCの通常1走査線を約1364マスタークロック、DRAMリフレッシュを約40クロック、DMAを8クロック/byteと仮定すると`(1364-40)/8=165.5B/scanline`が純転送時間の概算である。通常V-Blankを約37走査線と仮定した場合の理論比較は以下のとおり。

| 理論的なDMA時間枠 | 容量概算 | 7,168Bとの差 |
|---|---:|---:|
| V-Blank 37走査線 | 約6,124B | 約−1,044B |
| V-Blank＋下8走査線 | 約7,448B | 約＋280B |
| V-Blank＋上下各8走査線 | 約8,772B | 約＋1,604B |

**これらは使用可能バイト数の保証ではない。** 上側8ラインは通常V-Blankの後の次フィールド先頭に位置し、下側8ラインとは連続しない。通常DMAとHDMAは同じ8チャネルを共有し、HDMAの初期化はフレーム先頭で発生する。上下ブランキング時のDMAチャネル再利用、HV-IRQの実行時間、65C816のDMAレジスタ設定、VRAMアドレスの切替、パレット・テーブル・共有SRAM所有権の整合を含め、走査線単位で転送完了を検証する。下側8ライン＋V-Blankのみでは理論上の余裕が約280Bと小さい。52ラインに必要な部分タイルだけを更新する手法も検証対象とするが、その設定費用を含めた実測なしに転送量削減を見込まない。

## 4. CGRAM / BG1VOFS HDMA

各画像ラインの動的24色を**6色/走査線×4走査線**で非表示側のCGRAM A/B領域へ書き込む。HDMAのチャネルは次のとおり固定する。

| HDMA CH | PPUレジスタと転送モード | 1走査線の転送 |
|---|---|---:|
| 0 | `$2121` CGADD、モード0 | 1B（先頭色番号） |
| 1～6 | `$2122` CGDATA、各モード2 | 12B（6色×2B） |
| 7 | `$210E` BG1VOFS、モード2 | 2B（同一レジスタへ2回） |
| 合計 | 8チャネル | **15B** |

CH0でCGRAM先頭番号を指定し、CH1～6を順に`$2122`へ書き込む。各RGB555色は2Bで、CGRAMアドレスの自動インクリメントを利用する。HDMA基本時間の概算式`18+8×チャネル数+8×転送バイト数`によれば`18+8×8+8×15=202`マスタークロック/走査線となる。テーブル行カウンタ・再読み込み、PPUのCGRAM書込み可能時刻、複数チャネル間の正確な順序とオーバーヘッドはこの概算に加えて検証する。

208可視走査線でのレジスタ転送量は、CGADDが208B、RGB555が`24×52×2=2,496B`、BG1VOFSが416Bで、**合計3,120B/field**（HDMAテーブル管理バイトは別）となる。BG1VOFSは4走査線の間同じ画像行を参照するよう走査線ごとに補正する。VOFSは通常8bpp領域と動的領域の双方に共通適用されるため、固定タイルのA/B選択と左領域のタイル行参照を一緒に設計する。最初のA/B準備、行切替前の更新完了、次フィールドへの引継ぎ、PPU先読みを実測する。

## 5. 描画・バッファ・65C816への受渡し

1. RISC-Vが内蔵SRAMで頂点変換、投影、クリッピング、ポリゴン描画、Zテスト、テクスチャ参照を行い、フィールド別画像を生成する。
2. 左128画素は207色共通パレットの8bpp番号に量子化して8×8ビットプレーンへ変換する。右24画素はRGB555色列に変換し、CGRAMのA/B先頭アドレスとBG1VOFSを含むHDMAテーブル、固定8bppタイル、タイルマップを準備する。
3. RISC-VはFPGA AHBと共有MEM所有権制御を経て外部共有SRAMへ完成素材を配置する。65C816は通信窓`$5000`・FIFO/IRQで完成通知を受け取り、共有SRAMからVRAM DMA・CGRAM/BG1VOFS HDMAを実行する。FIFOをフレームバッファとして使用しない。
4. フィールド境界で素材・パレット参照・HDMAテーブル・MEM所有権を同期する。未完成素材を表示せず、DMA/HDMAチャネルの同時利用を避ける。

論理152×104の8bitリニアバッファは**15,808B**、16bit RGB555/Zバッファは各**31,616B**である。AG32内蔵SRAM128KiBには実行コード・スタック・テクスチャ・頂点・変換用一時領域も必要なため、実使用量を計測して配置する。

## 6. 検証手順と合格条件

| 工程 | 検証内容 |
|---|---|
| P0 | CH0→CH1～6のCGADD/CGDATA更新順序、6色/走査線の書込み可能期間、CH7のBG1VOFS同時利用を実測 |
| P1 | A/B固定タイルの色番号参照、表示中側を保持したまま4走査線で24色を更新できるか検証 |
| P2 | 上下各8走査線の強制ブランキング境界、HV-IRQ、HDMAの開始・停止・初期化とDMAチャネル共用を確認 |
| P3 | 7,168BのVRAM DMA完了時刻、タイル行切替、共有SRAM所有権とHDMAテーブルの一貫性を確認 |
| P4 | Mode 3で偶奇52＋52ラインを表示した場合の実際の垂直位置・独立行数・ちらつき・フィールド周波数を測定 |
| R0 | RISC-Vの3D描画、207色量子化、24色RGB555変換、タイル・HDMA素材生成を実装 |
| R1 | **152×104**での描画FPS、DMA/HDMA占有時間、VRAM/CGRAM更新量、CPU内蔵SRAM、FPGA LUT/FFを測定 |
| U0 | 共通表示経路によるUSB映像のフィールド受信・同期・遅延を測定 |

設計採用と性能検証完了は区別する。**CGRAM正常更新、VRAM DMA完了、追加ブランキング境界、偶奇フィールドの表示位置、RISC-V/65C816のMEM調停**をエミュレータおよび実機で検証する。
