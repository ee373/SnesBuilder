# 既存SFC ROMの互換性とイメージ変換

Rev.0.8 / 2026-11-19。

## 1. 標準マッピング

SFCBuilderはHiROM、ExHiROM、LoROM、ExLoROMの4形式を基本対応対象とする。通常のROMはAG256SL100 CPLDが5V→3.3V変換後のアドレスを高速に変換し、70nsの8MiB NORからSN74LVC8T245を経てSFCへデータを返す。SlowROM 200ns以内を必須とし、FastROM 120ns以内を達成する設計目標とする。

ゲームローダはROMヘッダのマップモード、実ファイルサイズ、既知のカートリッジ形式を照合して、HiROM系/LoROM系の選択、4MiB領域の選択、SRAM領域を決定する。ROMヘッダだけからExROM判定を確定させず、ゲーム固有のメモリマップと照合する。

## 2. 容量ミラーリング

NORの容量は8MiBとする。ROM容量に応じたミラーをアクセス中にCPLDで計算せず、**ARMゲームローダがNORへの書込み前に正しいミラー配置へ展開**する。

- 512KiB、1MiB、2MiBなどの小容量ROMは、該当するCPUアドレス窓で正しいデータが返るよう必要な物理スロットに複製する。
- 3MiBのような非2冪容量は、元カートリッジ固有のルールを保持したまま4MiB相当のイメージへ展開する。
- 5MiB、6MiBなど8MiB以下の容量も、ExROMのバンク構造に合わせて8MiBの物理アドレスへ展開する。
- 小容量LoROMは32KiBバンクを64KiBスロットに展開する構成を選択できる。ExLoROMなど容量の大きなROMは32KiBバンク構造をCPLDで生成する。

不足バイトを単に$FFなどで埋めて既存カートリッジのミラー規則と取り違えない。ROMの先頭に512バイトのコピー用ヘッダが存在する場合は書込み前に除去し、必要に応じてゲームヘッダ・チェックサム整合を確認する。NORに同一イメージが存在する場合はキャッシュ識別情報と書込済み配置を比較し、不要な消去/再書込みを省略する。

## 3. SRAM・通信・起動の整合

128KiB SRAMの基本マッピングはHiROM系8KiB窓、LoROM系32KiB窓をCPLDでデコードする。ゲームのセーブ容量が小さい場合は、セーブ領域の占有範囲とミラー規則をゲームパッケージに記録する。SRAM末尾8KiBは起動時のBIOS展開で上書きされるため、永続セーブに利用しない。

$5000–$5FFFにはSFCBuilderの通信レジスタを設定できる。既存ゲームがその領域を別用途に使用する場合は通信拡張を無効にし、通常のメモリマップと衝突させない。ブート時にはPSoCが6バイト固定値応答を行い、SRAM上のBIOSへ移る。ゲームのROMを実行する前に通常マッピングを有効化する。

## 4. 互換性テスト

LoROM/HiROM/ExLoROM/ExHiROMの各形式について、銀行境界、ROMヘッダ、リセット/割り込みベクタ、NORの物理A22、SRAM選択、容量ミラーの端点をテストする。FastROMを示すヘッダの動作は実機120ns測定が完了してからサポートを確定する。

ゲームがSA-1、Super FX、DSP、Cx4などの別の専用拡張チップを必要とする場合、その機能をAG256とPSoCが自動的に再現する仕様ではない。個別のソフトウェア実装・パッチが必要となる場合はゲームごとの互換性情報として扱う。標準対応対象は4種類のROMマッピングとSFCBuilder独自拡張インターフェースとする。
