# FPGA AHBインターフェースと本番タイミング

2026-11-20。対象はSFCBuilder Rev.0.9、AG32VF407VGT6（AGRV2KL100）。CPU側AHBは240 MHz、バス制御とFIRは共通の80 MHz、DSMは水晶由来の8 MHzで動作する。本番の既定ビルドは `fpga/build.ps1`、Supra Nativeのシードは1234。

## AHB信号一覧

RISC-Vがマスター、FPGAがスレーブとなる32 bitの `mem_ahb_*` 1系統を使用する。FPGAは要求と応答を保持し、240 MHzと80 MHzの間でトグルハンドシェイクにより1転送ずつ受け渡す。240 MHzの1周期は約4.167 ns、2周期は約8.333 ns。

| 信号 | 方向 | 幅 | 役割とサイクル |
|---|---|---:|---|
| `HADDR` | CPU → FPGA | 32 bit | バイトアドレス。要求受理エッジで取り込む。1周期制約 |
| `HTRANS` | CPU → FPGA | 2 bit | 転送種別。bit 1で有効転送を判定し、受理エッジで取り込む。bit 0は未使用。1周期制約 |
| `HWRITE` | CPU → FPGA | 1 bit | `0`は読出し、`1`は書込み。要求受理エッジで取り込む。1周期制約 |
| `HSIZE` | CPU → FPGA | 3 bit | `000`は8 bit、`001`は16 bit、`010`は32 bit。要求受理エッジで取り込む。1周期制約 |
| `HWDATA` | CPU → FPGA | 32 bit | 書込みデータ。アドレス受理の2 CPU周期後に取り込む。2周期制約 |
| `HREADY` | CPU側 → FPGA | 1 bit | AHBの進行状態。要求受理と応答が受理されたことの確認に使う。1周期制約 |
| `HRDATA` | FPGA → CPU | 32 bit | 読出しデータ。CPU側の応答レジスタへ先行して保存する。2周期制約 |
| `HREADYOUT` | FPGA → CPU側 | 1 bit | `0`で待機、`1`で完了可能。処理中はLowを保持する。信号経路は1周期制約 |
| `HRESP` | FPGA → CPU側 | 1 bit | `0`は正常、`1`はエラー。信号経路は1周期制約。エラーの応答手順は2周期 |
| `HBURST` | CPU → FPGA | 3 bit | バースト種別。現行RTLでは未使用 |

`slave_ahb_*` は固定値で無効化している。割り込みは別配線の `local_int[3:0]` を使う。bit 0は通信・貸出要求、bit 1はアプリ停止、bit 2は電源断、bit 3は予約。3本の割り込みにはSYSCLKで1段のレジスタを追加している。

## 結果取得までのサイクル

要求受理からCPUが結果を受け取るまでには80 MHz側の処理とクロック間の受け渡しが入り、全アクセス先で2 CPUサイクルを超える。周期数はアクセス先や転送サイズで変わる。

| CPUアドレス | 対象 | アクセス幅 | 要求から2 CPUサイクルで完了 |
|---|---|---|---|
| `0x60000000` ～ `0x6000000C` | 制御4レジスタ。MAP_CONFIG、PIN_STATUS、BOOT_CONTROL、BUS_CONTROL | 32 bit、4バイト境界 | いいえ。80 MHz側でレジスタ処理 |
| `0x60001000` ～ `0x60001030` | SFC通信13レジスタ。コマンド、返信、FIFO、IRQなど | 32 bit、4バイト間隔。有効データは下位8 bit | いいえ。80 MHz側でレジスタ・FIFO処理 |
| `0x60002000`、`0x60002004`、`0x60002008` | 音声PCM（書込み）、STATUS（読出し）、CONTROL（読書き） | 32 bit。PCMは左16 bitと右16 bit | いいえ。80 MHz側でFIFO・レジスタ処理 |
| `0x61000000` ～ `0x617FFFFF` | パラレルNOR、8 MiB | 8 / 16 / 32 bit、自然整列 | いいえ。外部8 bitバスで1 / 2 / 4回転送 |
| `0x62000000` ～ `0x6201FFFF` | 外部SRAM、128 KiB | 8 / 16 / 32 bit、自然整列 | いいえ。外部8 bitバスで1 / 2 / 4回転送 |

正常読出しは、CPU側のレジスタへ `HRDATA` を保存して2周期後に `HREADYOUT` を上げ、CPUがその次の立上りでデータを取り込む。エラー応答では、`HRESP=1` とともに `HREADYOUT=0` の周期を経て `HREADYOUT=1` を返し、受理されるまでエラーを保持する。`HRDATA` のSTAには保守的に8.333 nsの制約を設定している。

## 配置配線後のタイミング余裕

Supra Native `af.exe` 2024.08.b0、シード1234、EFFORT=high、FITTING=timing。以下は制約対象の最悪余裕で、単位はns。

| 経路 | セットアップ | 高速コーナーのセットアップ | ホールド | 高速コーナーのホールド |
|---|---:|---:|---:|---:|
| 全体 | +0.220 | +1.033 | +0.101 | +0.080 |

| 通常コーナーのセットアップ | 最悪余裕 |
|---|---:|
| CPU 240 MHz | +0.220 ns |
| バス・FIR 80 MHz | +1.666 ns |
| CPU → バス | +0.501 ns |
| バス → CPU | +0.743 ns |
| 割り込み経路 | +0.517 ns |

合成結果はLUT 1,784個、FF 999個、BRAM 3個。配置は1,934 / 2,112スライス（91.6%）。制約カバレッジは7,739 / 8,376接続（92.4%）。合格した出力は `fpga/rtl/top.bin`。レポートは `fpga/rtl/alta_db` に出力する。

採用バイナリのSHA-256は `CDF97381273FBC7B8BAE67F5BD1D4683FE7A721BC18EAA6200BAB4BCC3E14991`。本番手順で合成したネットリストと合格配置の入力を照合し、配置配線データを再読込みして4種のタイミング解析に合格したバイナリを採用した。同一シードの新規配置でも結果が変わるため、既定ビルドでは入力ハッシュが一致する同梱の合格済み配置を再解析する。[ビルド手順](../../fpga/README.md#ビルド)

`fpga/rtl/alta_db/setup_summary.rpt`（ビルド時生成） · `fpga/rtl/alta_db/setup_fast_summary.rpt`（ビルド時生成） · `fpga/rtl/alta_db/hold_summary.rpt`（ビルド時生成） · `fpga/rtl/alta_db/hold_fast_summary.rpt`（ビルド時生成）

RTLでは、連続AHBアクセス、エラー応答の保持と直後の正常アクセス、3本の割り込みの発生・解除、音声FIFOとFIR、電源断を含むNOR転送290件を確認した。外部バスの基板上タイミングとアナログ音声は実機で検証する。

## ソース管理された検証資料

本番の合格済み配置は [verified-route](../../fpga/verified-route/) の入力ハッシュと配置データで管理する。`fpga/rtl/top.bin`、`fpga/rtl/alta_db/`はビルド時の生成物であり、リポジトリのブランチ上にレポートファイルが常に存在するわけではない。検証数値を再確認する際には[再ビルド手順](../../fpga/README.md)の入力ハッシュ照合と配置配線後STAを実行する。
