# Rev.0.9 FPGAの合成使用率とタイミング検証

2026-11-20。対象はSFCBuilder Rev.0.9のAG32VF407VGT6（AGRV2KL100）。現行ビルドはRISC-V 240 MHz、バス・FIR 80 MHz、DSM 8 MHz。SlowROM 200 nsの必須条件とFastROM 120 nsの目標は、基板上でのデータ到着とセットアップの実測で判定する。

## 本番構成

2026-11-20採用版は、17 bitの音声経路、24 bitのDSM積分器、段階化したAHB応答、CPU割り込みへの追加レジスタを含む。配置配線後の最小セットアップ余裕は+0.220 ns、最小ホールド余裕は+0.080 ns。

本番の信号一覧、アクセス先と周期、タイミング余裕は[AHBインターフェース仕様](ahb-interface.md)を参照。以下の配置配線値は各時点の構成に対応する。

## CPU 160 MHz・FPGA 80 MHzの旧ビルド

CPU側のAHBとFPGA側のバス制御を分離した。CPU→FPGAとFPGA→CPUのセットアップ余裕はそれぞれ +1.660 ns、+2.498 ns。80 MHz側のストローブ、MEM所有権、SPIデコーダのクロック周期は従来と同じ。USB用PLL出力は60 MHz。

| 指標 | 160 MHzビルド |
|---|---:|
| CPU 160 MHzの最悪セットアップ余裕 | +1.826 ns |
| FPGA 80 MHzの最悪セットアップ余裕 | +3.571 ns |
| 高速コーナーを含む最悪ホールド余裕 | +0.294 ns |
| 製品用SDCの制約カバレッジ | 4,092 / 4,741（86.3%） |
| 論理セル / LUT / レジスタ | 1,005 / 804 / 580（各容量2,112） |
| 構成バイナリのSHA-256 | `1F5F190AD518E6517F797539B2DB7415811562BB4F90564696FDDDBE185E8EE3` |

配置後のSFCアドレスからMEMアドレスまでの遅延は17.690 ns、SFCアドレスからNOR /CEまでは18.433 ns。前回と同じ外付け部品条件で、通常NOR読出しの最長経路の概算は約99.2 ns。これはアドレス変化がNOR /CEへ届く経路の値で、基板配線、U5の有効化、SFCの入力到着差と受信セットアップは別途確認する。

## CPU 240 MHz・FPGA 80 MHzへの移行

応答データをCPU側の `HRDATA` レジスタに取り込み、次のSYSCLKで `HREADYOUT` を上げる。これによりCPUが転送完了としてデータを取り込むエッジは、データを出力したエッジの2周期後になる。読出しデータの先行確定と保持、連続するアクセス、AHB ERRORの2サイクル応答を含む6ケースを、240 MHz対80 MHzのクロック比でRTL検証した。

Supraの `set_multicycle_path 2` はセットアップとホールドの両方の検査エッジを動かした。試作ではCPU側の `HRDATA` 入力32本に `set_max_delay -to [get_pins {rv32|mem_ahb_hrdata*}] 8.333` を指定し、配線後の報告でセットアップ8.333 nsと通常の同一エッジのホールド検査を確認した。制御信号は通常の1周期制約で検査した。

| 配置配線後の最悪余裕 | 1周期追加、シード947 | 応答検出も1段追加、シード17 |
|---|---:|---:|
| `HRDATA` のセットアップ | +2.735 ns | +1.783 ns |
| `HRDATA` のホールド | +1.673 ns | +2.444 ns |
| CPU側のセットアップ | −0.910 ns | −0.230 ns |
| FPGA 80 MHz側のセットアップ | +0.248 ns | +0.658 ns |
| CPU→FPGAのセットアップ | −0.044 ns | −0.197 ns |
| FPGA→CPUのセットアップ | +0.292 ns | +0.056 ns |
| 報告された全クロックの最悪ホールド | +0.588 ns | +0.588 ns |

両試作とも4シードで `HRDATA` のセットアップとホールドを満たした。1周期追加版のシード947では要求トグルから読出しレジスタ群のクロックイネーブルまでの経路が最も厳しかった。応答検出を1段追加したシード17では、`local_int[0]` のCPUへの入力とGPIO6の出力イネーブルからFPGAのSPI選択回路への経路にセットアップ違反が残った。

### 割り込み出力とSPI選択入力を登録した現行構成

応答検出を追加した版に、CPU側の2段同期器の後ろから `local_int` を駆動する出力レジスタを1段追加した。SPI側ではGPIO6の選択値2ビットと出力イネーブル2ビットをBUSCLKで登録してからデコードする。Supra Nativeの合成でデコードが入力段の手前に移動したため、4ビットの入力段には `keep` を指定し、合成後にGPIOから各入力レジスタへ直接接続されていることを確認した。割り込みとSPI入力には追加のタイミング例外を設定していない。

| 配置配線後の最悪余裕 | CPU 240 MHz・FPGA 80 MHz、シード947 |
|---|---:|
| CPUへの割り込み入力のセットアップ | +0.409 ns |
| GPIOからSPI選択入力段へのセットアップ | +0.567 ns |
| `HRDATA` のセットアップ | +1.820 ns |
| 構成バイナリのSHA-256 | `913270031102B150BBA47C05CD0768B6112F627974027C42806FCC36EE305DA4` |

6シード中、シード947の配置結果が制約対象の全経路でセットアップとホールドを満たした。現行プロジェクトで生成した合成ネットリストと試作時のネットリストが一致することを確認し、合格した配置配線を現行のSDCで再解析して構成バイナリを再生成した。同じシードで新たに配置配線した場合にも経路が変わることを確認した。ビルドスクリプトは、タイミング違反時に合格済みバイナリを保持する。制約カバレッジは4,112 / 4,774（86.1%）。AHBの6ケース、SPIの11ケース（両方の `/CS` が同時にLowにならないこと、切替時の無選択、予約値、出力無効を含む）、電源断割り込みの3ケースを確認した試作RTLと、現行RTLは一致する。

割り込みの通知には1 SYSCLK周期、SPIの選択反映には1 BUSCLK周期が加わる。ファームウェアがSPIのデバイスを切り替える場合は、GPIO出力の変更から最大3 BUSCLK周期（37.5 ns）とデバイス側の `/CS` セットアップ時間を確保してからSCKを開始する。

### 現行ビルドの同期タイミング

| 経路 | 通常セットアップ | 高速コーナーのセットアップ | 高速コーナーのホールド |
|---|---:|---:|---:|
| CPU 240 MHz側 | +0.026 ns | +0.821 ns | +0.431 ns |
| FPGA 80 MHz側 | +1.062 ns | +2.225 ns | +0.420 ns |
| CPU → FPGA | +0.567 ns | +1.218 ns | +0.531 ns |
| FPGA → CPU | +0.814 ns | +1.570 ns | +0.294 ns |

CPU側の最悪セットアップは、AHB応答レジスタの `HREADYOUT` からRISC-VハードIPの `HREADY` を経て、FPGAのAHB状態機械のクロックイネーブルへ戻る1周期経路。CPUクロックの配置配線後Fmaxは241.488 MHz。BUSCLKの全周期経路は+1.073 ns。6.250 nsの半周期経路では、NORストローブから状態更新のクロックイネーブルまでの余裕が+1.062 ns、`power_sync` からNORストローブレジスタまでが+1.233 nsだった。高速コーナーで最も厳しいホールド経路は、BUSCLK側のAHB応答データからSYSCLK側の読出しレジスタまで。 [セットアップ報告](../../fpga/rtl/alta_db/setup_summary.rpt)・[高速コーナーのホールド報告](../../fpga/rtl/alta_db/hold_fast_summary.rpt)。

通常のNOR読出しでは、NORのアドレス・/CE・/OEの経路を並行に評価した。FPGAを通るアドレス経路は98.688 ns、/CE経路は99.144 ns、/OE経路は44.440 ns。入力バッファ6.3 ns、NORのアドレスおよび/CEからの最大アクセス時間70 ns（/OEからは15 ns）、U5のデータ伝搬4.5 nsを加えた。FastROMの120 nsに対する残りは約20.9 nsで、ここから基板配線、U5の有効化、SFC信号間の到着差、受信側セットアップを見込む。 [74LVC245Aデータシート](https://assets.nexperia.com/documents/data-sheet/74LVC_LVCH245A.pdf)・[S29GL064Sデータシート](https://www.infineon.com/assets/row/public/documents/10/49/infineon-s29gl064s-64-mbit8-mbyte3-datasheet-en.pdf)・[SN74LVC8T245データシート](https://www.ti.com/lit/ds/symlink/sn74lvc8t245.pdf)。

## SFC非同期経路の端子間遅延

配置配線済みデータを読み込み、表の経路に調査用の最大遅延制約を与えて、AG32の入力パッドから出力パッドまでの経路遅延を抽出した。A6～A11のSFC側経路はAG32を通らず、U1から外部メモリへ直接入る。

| FPGA端子間の経路 | 最悪端子対 | 最大遅延 |
|---|---|---:|
| SFCアドレス → MEMアドレス | PIN45 → PIN97 | 16.194 ns |
| SFCアドレス → NOR /CE | PIN45 → PIN61 | 14.620 ns |
| SFC /ROMSEL → NOR /CE | PIN48 → PIN61 | 13.179 ns |
| SFC /RD → NOR /CE | PIN38 → PIN61 | 13.599 ns |
| SFC /RD → MEM /OE | PIN38 → PIN63 | 13.991 ns |
| SFCアドレス・制御 → SRAM /CE | PIN45 → PIN62 | 15.582 ns |
| SFCアドレス・制御 → SRAM /WE | PIN41 → PIN64 | 15.955 ns |
| SFCアドレス・制御 → U5有効化制御 | PIN45 → PIN67 | 17.651 ns |
| SFCアドレス・制御 → 特殊応答のMEMデータ端子 | PIN45 → PIN81 | 18.629 ns |
| POWER_FAIL → 主要MEM・SFCバス遮断制御 | PIN24 → PIN67 | 14.715 ns |

「SFCアドレス・制御」はAG32に入るアドレス18本と `/RD`、`/WR`、`/ROMSEL` を対象とした。「主要MEM・SFCバス遮断制御」はPIN61～65とPIN67のうち、入力から直接伝搬する経路を対象とした。製品用SDCに非同期I/Oの制約は追加していない。 [バス仕様と検証目標](../bus.md)・[ピン制約](../../fpga/top.ve)。

### 通常NOR読出しの概算

アドレス、`/CE`、`/OE` の各到着経路は並行して進む。個別に外付け部品の最大遅延を加えると、アドレス変換を通る経路が最も長い。ここではSFC側のアドレスと制御の到着差を含めていない。

| 区間 | 使用した遅延 |
|---|---:|
| SFC → 入力バッファ74LVC245A | 6.3 ns |
| AG32のアドレス端子間 | 16.194 ns |
| パラレルNORのアドレスアクセス | 70 ns |
| U5のデータ伝搬（B→A） | 4.5 ns |
| **合計** | **96.994 ns** |

入力バッファは3.0～3.6 V、−40～+85 °Cの最大値、U5はVCCA=5 V ±0.5 V、VCCB=3.3 V ±0.3 Vの最大値を使用した。概算を差し引いた残りの予算は、SlowROM 200 nsで約103 ns、FastROM 120 nsで約23 ns。ここから基板配線と負荷、U5のMOSFET経由の有効化、SFC側の入力到着差と受信セットアップを見込む。 [Nexperia 74LVC245A](https://assets.nexperia.com/documents/data-sheet/74LVC_LVCH245A.pdf)・[Infineon S29GL064S70TFI023](https://www.infineon.com/part/S29GL064S70TFI023)・[TI SN74LVC8T245](https://www.ti.com/lit/ds/symlink/sn74lvc8t245.pdf)。

### 再解析方法

配置配線済みの `alta_db`、`af_run.tcl`、`top.sdc`、`top.vex`、`top.qsf`、`top.asf`、`top.pre.asf`、`top.post.asf` を一時フォルダに複製する。`af_run.tcl` の配線データ読込み後、標準のタイミング報告の直前に次のような端子指定を追加し、`FLOW=LOAD`、`MODE=NATIVE`、`SEED=947`、`RESULT_DIR=.` で実行する。100 nsは未制約経路を報告に載せるための解析上の値で、結果には `data` 欄の遅延値を採用する。高速コーナーの報告は `rt_report_timing_fast=true` で有効にする。

```tcl
set source [get_ports PIN_48]
set target [get_ports PIN_61]
set_max_delay -from $source -to $target 100
report_timing -setup -from $source -to $target -verbose 2 -file romsel_to_ce.rpt
```

## 実機確認

- SFCのアドレス、`/ROMSEL`、`/RD` とSFC側D0～D7を同時に測定し、SlowROMの200 nsとFastROMの120 nsに対する到着余裕を確かめる。
- U1/U6のアドレス切替とU5の方向・出力許可切替を測定し、外部メモリとFPGAのデータ駆動の重なりを確認する。
- POWER_FAIL発生時の制御信号とバッファ出力を測定し、CPUへの引渡し時にバス競合や逆給電がないことを確かめる。進行中だったSFCのSRAM書込み結果は保証対象外。 [電源断時の仕様](../power-cic.md)。

今回の調査ではRTL、製品用SDC、構成バイナリを変更していない。
